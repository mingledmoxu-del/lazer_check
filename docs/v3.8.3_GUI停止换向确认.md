# v3.8.3 GUI停止换向确认

用户报告：定角运动未完成时停止，再点反向，电机似乎继续原方向。检查发现GUI与SDK的停止确认不一致：SDK连续两次零速后才继续，GUI此前一次零速即允许后续动作；GUI的旧运动监测、报警读取和发送动作定时回调也没有按操作代次作废。

本版仅修正GUI：停止和新的定角操作递增操作代次，旧代次的运动相关定时回调不再执行；停止清除待发动作，停止中点击新方向只保留最新请求并继续停止确认；连续两次实际零速后，再检查报警并发送最新方向的带符号角度命令。非零速会重置零速计数。没有修改角度正负含义、限位保护或SDK速度换算。

回归测试使用GUI真实命令分发器，构造旧正向待发回调、停止、反向，确认旧回调不再写入通信，第一次零速不启动，第二次零速加无报警后发送0x14且角度为−5000毫度。

这能修正已找到的GUI流程隐患，不能仅凭代码断言现场的“继续旧方向”就是同一原因。需要实际日志核对TX角度符号、STOP确认、反向应答；若新的负角度已成功下发而机械仍旧向，则还需检查共享固件/驱动器执行。API没有Tkinter定时回调，但与GUI共享板端执行路径，不承诺硬件方向问题只影响GUI。

继续配套v3.8.1固件，本次无需重烧。关闭旧GUI，运行app/start_simple.bat，标题应为v3.8.3。174项Python测试通过，尚未实机复现确认。

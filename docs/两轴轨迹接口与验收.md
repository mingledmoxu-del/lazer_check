# v3.0 两轴缓冲轨迹：集成接口与验收

> 本文保留v3.0/v3.1的设计和历史验收说明。当前v3.2已改为115200/8N2、允许50～500ms周期，并新增实际位置、共同减速和返回预载；升级与新增API以[v3.2操作说明](v3.2_115200与轨迹恢复.md)为准，需要同时更新固件和两台驱动器的通信参数。

## 1. 本次实际增加了什么

旧定角、回零和停止接口保留。新增完整预上传的两轴时间轨迹，STM32以共同起始时刻进行线性插补，利用位置反馈和速度前馈／位置比例修正更新两台驱动器PA24；模式只在启动时初始化一次，运行中允许正、负、零速度，不再每点停机和重新切模式。

这是一条基于现有RS485接线的**实验性低频跟随路线**，不是硬同步脉冲插补，也不是已验证的“5秒精确画空间圆”。两轴共用时间基准，但读反馈、写速度是依次进行的。没有修改波特率、SON、编码器零位或硬件接线。

- PC↔STM32：115200 / 8N1；STM32↔驱动器：仍为9600 / 8N2。
- 控制周期可配置250～500ms，最多约4次双轴更新／秒；通讯超时、参数读回会增加实际周期。
- 5秒轨迹大约20次更新。必须测量平滑度、轨迹误差、更新耗时和相位差，不能只凭界面计时判断达标。
- 上位机上传整条有限轨迹；目前没有运动中追加／替换轨迹点的流式接口。运行中速度由STM32更新，而不是PC实时推送。
- 不支持在运行中更改范围、重新回零、改加减速或混用旧运动接口。停止整个任务后，才能上传新的轨迹。

## 2. 坐标、单位与前置条件

两轴角度均为50:1减速器输出角度。电机1使用既有水平姿态：水平0°、传感器最终回零参考+25°、默认范围−35°～+35°；电机2仍为其建立参考后的相对坐标。

每次启动必须满足：

1. 两轴参考均有效，P3-32=3、PA11与捕获参考时相同；两轴软范围均已启用，无驱动报警或待处理保护。
2. 两轴实际速度为0，并已经人工／通过现有定位接口移到轨迹首点附近，误差不超过配置的终点容差。轨迹模式不会猜方向或自动走到起点。
3. 不在自动连续旋转、回零或其他停止确认中。
4. 全部轨迹点在各轴软范围内，并距边界至少1°；线性段不会越出相邻点的角度包络。不能用扩大最大跟随误差解决机械范围不足。
5. 已分配的正／负限位正常。中间原点不视为端点保护；原点设为端点时，任何相应触发会终止轨迹。

上传校验和启动前均检查约束；最终以下位机结果为准。重新上电后，轨迹、会话、参考和策略全部丢失，不自动恢复运行。

## 3. 上位机操作

入口：主窗口“自动连续旋转”区域右侧 **两轴轨迹试验**。

### v3.1一键小幅测试

如果只想确认两台电机能连续一起运动，主窗口或本窗口点击 **一键双轴小幅调试** 即可，无需按下面普通轨迹步骤填写参数／预定位。它先读取两轴参考、软范围、转速、报警，确认后自动上传并启动：以当前位置为中心，两轴同相±1～2°，20秒往返一圈，回到起点附近。余量不足3°、参考无效、软范围关闭或有故障时拒绝；不自动回零、扩大范围或更改SON。幅度会依据两轴共同可用空间缩小，固定控制周期250ms、速度上限1.5°/秒、加速度3°/秒²、误差上限0.75°、终点容差0.3°。准备／上传中停止、关闭或通信异常会取消自动启动。已有v3.0固件只需重启新版上位机，固件协议不变。

### 普通CSV／圆轨迹试验

1. 先在原调试面板建立两轴参考、配置原点和软范围，确认机械方向及电平。
2. 生成离线正弦示例或导入CSV。示例只是两轴角度空间的正弦／余弦组合，不是经过机构逆运动学标定的末端圆；真实空间圆应由完整软件生成角度点。
3. 查看预览中的首点，两轴通过现有坐标定位功能分别走到首点并确认停稳。先做小幅度、长周期，例如幅度2°、周期20秒；不要第一次就贴边或追求5秒。
4. 点击“上传并校验（不启动）”。完整上传后才允许启动，参数更改后需要重新上传。
5. 点击“启动已校验轨迹”，人工确认后共同启动。查看状态、缓存角度、跟随误差、最大调度间隔、本轮通讯耗时。
6. “停止两轴”和主窗口红色停止均会取消整个正在执行的轨迹；停止后不能续跑旧缓冲，必须重新上传。关窗口／断开串口也会尽力请求停止，但无法保证停稳。

轨迹运行中，普通自动反馈刷新暂停；轨迹状态查询不额外访问驱动器。通过协议读取普通位置／速度／报警时也返回最近缓存，未提供与当前时刻完全同步的快照；缓存速度响应的运行状态字段为未知0。轨迹缓存PA95为未知65535，不要把它当作真实编码器位数。

## 4. CSV与离线点模型

CSV UTF-8／UTF-8 BOM，表头固定：

```csv
time_s,axis1_deg,axis2_deg
0,5,0
2.5,6,1
5,5,0
```

这是折线示例，不是圆。时间从0开始，严格递增，量化到1ms后相邻至少50ms。2～128点，总时长1～600秒。角度分辨率0.001°，正数不一定等于机构的物理正方向，须以现场标定为准。

末点时间是计划运动段的时长，不包含上传、预定位、驱动器模式初始化、末点收敛和两轴停稳确认。超出跟随误差上限会失败，不会将“计时到了”直接当作完成。

## 5. 独立Python接口

复制整个`app`目录；GUI和接口不能同时占同一串口。导入模块不会连接或运动。正式软件在工作线程／动作队列中调用同步接口，不要阻塞UI线程，不要多个线程同时调度复合动作。

**同事软件已有预设路径时，优先使用“提前预载、触发时只启动”的调用流程。** [上位机README](../app/README.md)开头的“同事程序已有预设轨迹”章节提供可复制封装、READY状态处理及失效重载规则。预载阶段调用`prepare_trajectory`，触发时只调用`start_trajectory`；这不改变实际上传速率或运行更新频率，也不提供Flash保存／多轨迹缓存。

```python
from app import MotorController, TrajectoryPoint, joint_ellipse

# 只计算，不连接、不运动；真实空间路径应替换成同事计算出的角度点。
points = joint_ellipse(center1=0, center2=0, amplitude1=2, amplitude2=2,
                       period_s=20, cycles=1)
print("首点", points[0])  # 电机1=+2°、电机2=0°；需先安全预定位。

# 以下仅在现场参考、范围、起点和急停均已核实后执行：
# with MotorController("COM6", timeout=4.0) as motors:
#     prepared = motors.prepare_trajectory(points, max_speed=3, max_accel=5,
#         max_error=1.5, tolerance=0.3)
#     input("核实现场和首点；按回车启动两轴：")
#     motors.start_trajectory(prepared.session)
#     finished = motors.wait_trajectory(prepared.session, timeout=35)
#     print(finished)
```

| 接口 | 行为 |
| --- | --- |
| `TrajectoryPoint(time_s, axis1_deg, axis2_deg)` | 一个带时间的两轴输出角度点 |
| `joint_ellipse(...)` | 离线角度空间示例生成器，默认32段／圈，总点数仍须≤128 |
| `prepare_trajectory(points, session=None, cycle_ms=250, max_speed=20, max_accel=30, max_error=5, tolerance=0.5)` | 先本地校验，再探测固件能力、停止旧动作、顺序上传并整体校验；返回已校验状态，不启动 |
| `start_trajectory(session)` | 明确启动已校验会话；要求两轴已在首点，启动后台心跳，不自动重试 |
| `get_trajectory_status()` | 返回下位机缓存状态，含会话、阶段、故障、时间、点数、周期统计、位置与误差；`feedback_available`为False时不可将默认0当位置 |
| `wait_trajectory(session, timeout=30)` | 仅状态DONE算完成；失败／取消抛异常，等待超时请求停止两轴；timeout应覆盖计划时长及收敛／停稳余量 |
| `stop_trajectory(wait=True, timeout=10)` | 请求停止整个任务及两轴，默认等待停稳；不续跑旧任务 |
| `stop(1)`／`stop(2)` | SDK拥有运行中的轨迹会话时会转为整组停止；固件运行轨迹时，任何一轴的旧停止命令也终止整组 |
| `check_auto_rotation()` | 兼容名称，同时用于检查轨迹心跳后台异常；正式软件仍须周期检查 |

`max_speed`单位°/秒（最大60），`max_accel`单位°/秒²（最大120），`max_error`为0.5～10°，`tolerance`为0.05～1°且小于max_error。它们约束计划段速度、段间近似加速度及离散速度更新；不等于实物加速度硬保证。实际过渡还取决于驱动器PA40／41／42、负载及通讯周期，需调试。

会话号1～65535，一次上传使用一个新会话号；不能立即复用固件当前保存的会话号。SDK默认自动产生，不应缓存后无限重用。重复启动、停止后的迟到启动、迟到心跳不会恢复旧任务。上传失败不自动重发点；重新建立新会话再上传。

旧固件会拒绝0x34能力探测，SDK不会在探测失败后继续停止／上传。新上位机必须配套烧录v3.0固件；SDK读取反馈时也仍须使用相同的姿态标定约定。

## 6. 新增协议（现有AA55帧／CRC16不变）

轨迹控制统一使用device=1代表整个双轴任务，不是只控制电机1。parameter为非零session；状态读取用0，组停止可用0停止任意当前会话。

| 命令 | 请求数据（大端） | 含义 |
| --- | --- | --- |
| 0x30 BEGIN | `uint16 count, uint16 cycle_ms, int32 max_speed, int32 max_accel, int32 max_error, int32 tolerance` | 建立上传会话；后四项×1000 |
| 0x31 POINT | `uint16 index, uint32 time_ms, int32 angle1, int32 angle2` | 顺序上传，index从0开始，角度×1000 |
| 0x32 SEAL | 无 | 所有点完整、范围／速度／段间加速度通过才进入READY |
| 0x33 START | 无 | 验证参考、起点、限位后初始化两轴速度模式，共同开始计时 |
| 0x34 STATUS | 无，parameter=0 | 缓存状态，不增加驱动器查询 |
| 0x35 STOP | 无 | 两轴停止，取消缓冲执行；也能停止轨迹以外的两轴普通运动 |
| 0x36 KEEPALIVE | 无 | 仅给RUNNING／SETTLING续期；终态只回报状态，不重启 |

响应数据固定40字节，Python格式`>HBBHHIIIIiiii`：

```text
session:u16, state:u8, fault:u8, count:u16, uploaded:u16,
elapsed_ms:u32, duration_ms:u32, max_gap_ms:u32, last_cycle_ms:u32,
actual1_mdeg:i32, actual2_mdeg:i32, error1_mdeg:i32, error2_mdeg:i32
```

原有响应Status字段仍表示本条请求是否成功；轨迹state/fault是另一层状态。不能只看Status=0就认定正在运行或已到位。

state：0空闲、1上传、2READY、3RUNNING、4末点收敛、5停止确认、6DONE、7FAULT、8CANCELLED。

fault：0无、1人工停止、2参考失效、3范围／制动余量不足、4限位、5通讯故障、6驱动报警、7跟随误差、8调度超过1秒、9心跳丢失、10未停在起点、11数据错误、12收敛超时。

## 7. 保护和时序限制

- SDK每约1秒／GUI每约0.75秒发心跳；3秒未续期请求两轴停止。3秒是租约期限，不是停止时间保证。
- 两轴任一故障、有效端点输入触发或短边沿锁存、误差超限、实际越界，均取消整组并请求两轴停止。即使第一台通信失败，也继续尝试停止第二台。
- 任一控制更新间隔或本轮采集耗时超过1秒会失败，不通过跳过大量轨迹来追赶。状态记录最大更新间隔和本轮耗时，真实串行写入偏差仍须测量。
- P3-32与PA11在启动时验证，运行中约每秒复核；两者变化／通讯结果不确定时参考失效，必须重新核查。其他配置通过本协议在运行中被锁定，不允许外部程序／面板并行改驱动器参数。
- 运行按速度、预计最长通信间隔及理想制动距离预留边界余量，不足则停机；不能把1°固定点余量当成任何速度下都安全。
- 到达末点时间后速度前馈归零，最多5秒闭环收敛；两轴进入容差、反馈零速后仍再执行组停止确认，只有DONE算完成。计时结束、写速度成功或单次零速都不是完成证明。
- 主循环／RS485是阻塞式，无法提供硬实时故障停机，禁止在中断里调用Modbus补救。此功能不代替硬件急停、驱动器硬限位或安全回路。

## 8. 必须完成的实机验收

1. 单轴方向、反馈单位、50:1及参考复测，再检查两轴范围和急停。
2. 小幅度、长周期、起点正确的双轴轨迹；记录状态和实体角度，确认符号、跟随误差及串行更新耗时。
3. 中途停止：两轴均停稳；旧会话启动／续期不能恢复运动。
4. 测试起点不匹配、未建立参考、轨迹越界、短限位边沿、心跳中断、驱动器通信故障；验证另一轴也停机。带负载试验应先降低速度并留大余量，不能靠碰机械端点验收。
5. 再逐步缩短周期至5秒，观察物理轨迹、最大误差、抖动和相位差。若不满足同事要求，下一步评估驱动器更高波特率及脉冲＋方向硬件方案，不取消保护强行通过。

自动模拟测试只验证协议、状态转移及停机请求，不验证机械精度。当前尚未进行此功能的实机验收。

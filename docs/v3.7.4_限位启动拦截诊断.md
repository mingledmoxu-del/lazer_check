# v3.7.4 限位启动拦截诊断

本次仅更新上位机，不改固件的限位保护和高电平触发配置，继续配套 v3.7.2 H743 网口固件。

复位启动报状态 0x08，且此前配置及读回已成功时，固件的专用搜索入口会因 DI0 或 DI2 被判定有效而拒绝启动。机械上没有遮挡并不能证明 MCU 输入电平为低，需核对实测输入；此更新不直接改变极性或跳过保护。

修复此前失败后不读取输入、只显示笼统错误的诊断缺口。现在窗口默认刷新电机1反馈，保留“读取限位状态”按钮（只读配置与反馈）；启动因限位失败后自动读取反馈，并继续显示“复位未启动”和具体有效通道、DI0/DI2 原始电平。优先处理复位窗口任务，避免慢业务轮询持续占用通信而延后输入状态读取。

现场核对：头部接近水平、两只限位均未触发时读取一次；保持电机停止，分别人工触发 DI0 和 DI2，记录原始电平变化。例如 MCU 高电平触发应为未触发 raw=0、触发 raw=1。若未触发为1而触发为0，则实际采样极性与当前配置不一致；若始终不变，则需先核查通道、供电和输入回路，不能仅改软件极性。

某些反馈查询需要伺服驱动器响应。若出现通信失败，当前电平保持未知，不能据此判定限位状态。网络只允许一个上位机连接时，额外诊断客户端可能被板端拒绝，应通过已连接的界面读取。

157 项 Python 测试通过，新增测试覆盖启动失败自动查询、具体两路电平显示、保留错误状态及不重发运动。未进行电机实测，现场原因仍需根据读数确认。

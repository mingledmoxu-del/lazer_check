# P100S 首次 RS485 速度调试

本版本使用 USART3：9600/8N2、从站 1；USART1：115200/8N1 输出日志。
PC10=TX、PC11=RX、PC12=方向，高发送低接收。保留原有板卡接线定义。

## 上电前

仅适用于固定电机、脱离机械负载的台架速度试验。确认可立即切断驱动器电源。
**STM32 复位、暂停调试器、拔掉 RS485 均不能保证电机停止。暂停 CPU 会冻结软件自动停止计时。**
上电不写任何参数，不自动使能；这也不会清除驱动器原先保存的强制使能。

面板核对并按手册保存/复位：

| 参数 | 本版要求 |
|---|---|
| PA-71/72/73 | 1 / 96 / 0 |
| PA-4 / PA-22 | 1 / 1 |
| PA-24 | 0 |
| PA-40 / PA-41 | 100 / 100 |
| PA-53 | 0：面板保存值也应为 0 |
| P3-0～P3-3 | 1、2、3、4 |
| P3-4、P3-5 | 0、0 |
| P3-15～P3-19 | 全部为 0（本次台架要求，不是通用设备配置） |
| P3-30 | 0，禁用虚拟输入 |

本版只检查这些配置，不会自动覆盖参数、解除限位或清除报警。
P3-15 如此前设过 1，需要先在面板清除并保存。实际 DI 端子保持未接控制信号。
手册 PA-53 定义为软件强制使能。本版通过 **PA-53 暂存地址 0x00B5** 操作使能，
通过 **PA-24 暂存地址 0x0098** 操作速度，均读回普通地址核对。
不再使用 P3-15 置位使能，不循环写 EEPROM。

## 编译与下载

在 `LightCheck` 子目录运行 `cmake --preset Debug`、`cmake --build --preset Debug`。
下载 `LightCheck/build/Debug/LightCheck.elf`。打开 USART1 串口监视器，115200、8N1。
串口只输出日志，不接收文本控制命令。

## 调试器操作

添加 `servo_bench` 和 `servo_motor` 到 Watch / Live Expressions。
**只修改 `servo_bench.command` 和 `servo_bench.rpm`，不要修改 state、计时及诊断字段。**
优先使用运行中的变量写入；若工具必须暂停才能修改，试转期间不得依赖软件超时停机。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 观察日志 | `poll=0 valid=1 alarm=0 drive=1` |
| 2 | `servo_bench.command=1` | 只读检查；`result=0 state=1` |
| 3 | `servo_bench.command=2` | 重新检查、零速读回、暂存使能；`result=0 state=2`，随后 `drive=3` |
| 4 | `servo_bench.rpm=50`，然后 `command=3` | 再次检查，通过后试转；`result=0 state=3` |
| 5 | 保持 CPU 运行 | 约 2 秒后写零速，`state=4`；反馈低于等于 5 rpm 后解除使能，`state=1 drive=1` |
| 6 | 反转试验 | 重新执行步骤 3，然后 `rpm=-50`、`command=3` |

使能后 15 秒未启动，会自动进入停止流程，避免无限等待。
试转范围为 -100～100 rpm，零值及超范围 RUN 命令被拒绝。
每条 command 执行前清零为 0；必须等待该条结果后再发下一条，不能批量写入多个命令。

- `command=4`：写零速，等反馈接近零后解除使能。3 秒仍未达到阈值则尝试解除使能并锁定故障。
- `command=5`：尝试写零速后立即解除使能，不等待减速，电机可能自由滑行。
- 完成试验确认 `state=1 drive=1 speed` 接近 0，再结束调试。

## 诊断

state：0=未知；1=已核对未使能；2=已发使能并读回；3=已发试转；4=停止中；5=故障。
state=2/3 是软件命令状态，实际驱动状态以最新成功读取的 drive 和速度反馈为准。

`servo_bench.result` 保留最近命令结果：0 成功，1 参数/前置条件不满足，2 忙，3 超时，
4 UART 错误，5 帧错误，6 CRC 错误，7 驱动器异常响应。
`failed_address` 为失败寄存器地址（0xFFFF 表示没有具体地址），`actual/expected` 是读回值与要求值，
仅读取成功但值不符时有比较意义；`exception_code` 保存相关异常码。
例如地址 0x0004 就是 PA-4，0x010F 是 P3-15。

`poll_result` 是最近状态轮询结果；失败时日志内速度/drive 可能是旧值，不能据此认为已停止。
`stop_result/disable_result` 是最近停止处理结果，不代表每次轮询重新确认。

通信失败、报警、驱动状态异常时，主动控制阶段会独立尝试零速和解除使能，随后进入故障状态。
写超时可能已经被驱动器执行，不自动重复运动命令。故障后先排查、确认停止，再重新 CHECK。
断线时这些请求可能都失败，软件没有独立硬件急停能力。

若固件不支持 P3-30、0x1016 或 PA 暂存读回约定，检查会失败并拒绝运动；记录地址和异常码，
核对目标驱动器型号/版本后再适配，不要跳过检查强行运行。

## 验证范围

已添加 `tests/test_p100s_bench.c`，以模拟 Modbus 驱动器验证：上电只读、模式/强制使能/非零初速拒绝、
速度限幅、正负数传输、定时停止、停止超时、报警、通信故障、写已执行但回包超时、写回不符及解除使能失败。
主机模拟不能验证真实接线、收发器极性、固件寄存器兼容性和实际机械停止行为。

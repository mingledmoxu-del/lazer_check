# v3.9.3：缩短应答准备与日志显示阻塞

配套：H743 固件、上位机与 SDK 源码。保持 v3.9.2 的真实输出轴 rpm、默认 ±0.2°、原有双轴/预载 API 协议。未进行本版实机运动测试，不承诺固定毫秒数。

## 已发现的开销

用户截图中速度为1 rpm，应答约0.485～0.688秒；用户反馈3 rpm时，到位→停稳约0.25～0.5秒，而应答没有随速度明显变化。这符合准备与通信开销独立于运动速度的情况，但不能把应答全部解释为网络延迟。

本机 `app/logs/motion_timing.jsonl` 中，2026-10-23 15:59:47～15:59:56 的六条双轴应答，板端两轴准备分别约54～55毫秒，合计108～109毫秒。主机日志另含发送前准备和处理应答的时间；同一数据包两轴日志时间戳相差几十毫秒。它们是该日志批次的数据，不保证与截图为同一轮。

代码中逐条 Tk 文本插入/滚动发生在收发、状态处理的调用路径上；同一包逐轴记录时又各自读取时钟，会把前一条日志处理时间计入后一轴。不能据此认定板端本身一直需要0.5秒。

## 本次修改

1. **每轴参数合并为两个当前读取块**：P3-0～P3-32共33字；PA11～PA42共32字。分别提取输入映射、强制输入、编码反馈方式、每转计数、速度源、速度命令及减速/平滑参数。原厂通讯说明允许每次最多100字，地址与数量均在此范围内。
2. **兼容拒绝范围读取的驱动器**：明确Modbus异常时回退只读取需要的参数，并在本次板端运行期间记住该轴不支持对应范围；每次仍读取实际参数，不缓存参数值。CRC、超时、IO错误直接失败，不作为能力拒绝，不隐式重试运动命令。
3. **去掉同一指令内的重复空闲保护轮询**：仅在两轴点位/预载点运行分派、两轴均无活动任务时，由紧接着的定位准备读取实际状态/单位并检查当前位置与目标范围。硬件及双限位边沿、待停止、回零、连续运动、轨迹处理仍按原逻辑执行。标志在该轮任务后立即清除。
4. **日志界面批量刷新**：`_log()`先入队，每50ms批量插入/滚动一次；显示保留最多2000行。详细运动事件继续写入 `app/logs/motion_timing.jsonl`。不会因为日志显示而省略应答校验或将未完成动作标记完成。
5. **同一双轴包共用发送/应答时间戳**：修复逐轴记录产生的虚假时间差。SDK已有API和实际rpm单位不变；自定义 `timing_callback` 仍同步调用，集成端应将重IO或UI刷新移出回调。
6. **修复CSV导出**：v3.9.2新增 `board_prep/ack_other` 后，导出字段清单漏同步，写完表头即因额外字段报错。本版同步15列并增加实际写入/回读测试，无记录时不再生成只有表头的CSV。用户提供的 `csv/csv1.csv` 只有表头，保持原文件不改。

在“速度模式已准备、块读取支持、此前无可复用完成证据”的主机C测试里，双轴启动总共只需4次参数块读取和4次实际状态读取，无非零速度写入；此前已完成的点可沿用既有双零证明并用本次新零速重验。冷启动模式切换、外部参数改变或异常仍会增加核验/停止耗时，因此这不是所有场景固定的事务数。

## 同事/API使用

接口及返回保持兼容：`move_axes_to()`、`preload_route()`、`run_preloaded_point()`、`move_preloaded_point_and_wait()` 不改参数。速度1表示实际1 rpm。预载只上传，之后每次按点编号运行一个目标；正常完成后直接复用返回的 `positions`，无需再停止并做一次全量核验。

`board_prepare_ms`是应答内两轴准备计时，不含全部板端分派工作；`accepted_ms`/GUI `ack` 是主机端应答耗时。GUI `ack_other=max(0, ack - sum(board_prepare_ms)/1000)` 包含其余板端调度、传输、主机处理，不能单独标为网络时间。

## 复测方法

同步重烧本版固件并重启本版上位机。先完成两轴参考，同一轨迹分别用真实1 rpm和3 rpm测试，容差固定±0.2°。完成后在同一计时窗口导出CSV，保留“应答、板端双轴准备、应答其余、到位→停稳、联动总耗时”。不要将第一段原本已在目标的记录与实际移动段混合平均。

应答开销应优先比较同速度、同路线、同容差的旧版/新版；速度改变主要影响运动及末段，不应据此推断通信收益。1秒是优化目标；机械移动、光斑振动和实际停稳时间仍需现场验证。

## 验证

219项Python测试、15组C主机测试及H743 Debug构建通过。回归覆盖块读取拒绝后的回退、回退仍读取变化的输入映射、CRC/超时不重试、当前位置越界拒绝、两轴失败同时停止、±0.2°双零完成、CSV新增字段、日志批处理及同包时间戳；Tk界面与2050行日志批量显示检查通过。没有烧录或启动电机。

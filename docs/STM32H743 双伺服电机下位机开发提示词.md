请帮我开发一套 STM32H743 下位机程序。

系统用途：

PC 上位机通过串口向 STM32H743 发送控制命令，STM32H743 解析命令后，通过 RS485 / Modbus RTU 控制两台 P100S 伺服驱动器。

当前第一阶段主要实现：

- PC 与 STM32 串口通信
- STM32 自定义协议解析
- 两台伺服驱动器地址区分
- P100S PA 参数读取
- P100S PA 参数修改
- RS485 Modbus RTU 通信
- 执行结果返回 PC

后续还会增加：

- Servo ON/OFF
- 启停控制
- 速度读取
- 位置读取
- 报警读取
- 报警复位
- 激光检测仪
- DI/DO
- 自动检测流程

因此程序必须模块化设计。

---

# 一、硬件架构

总体通信结构：

```text
PC 上位机
    │
    │ USB转串口
    │ UART
    ▼
STM32H743
    │
    │ UART + RS485收发器
    ▼
P100S Servo #1
    │
    │ CN4 RJ45
    ▼
P100S Servo #2 CN3
```

两台 P100S 在同一条 RS485 总线上。

例如：

```text
Motor 1：
Modbus Slave ID = 1

Motor 2：
Modbus Slave ID = 2
```

STM32H743 是 Modbus RTU Master。

两台 P100S 是 Modbus RTU Slave。

# 四、RS485方向控制

RS485 使用半双工收发器。

假设：

```text
DE / RE
```

由 STM32 GPIO 控制。

例如：

```c
RS485_TX_EN()
RS485_RX_EN()
```

发送前：

```text
DE = 1
```

发送完毕：

```text
等待 UART TC
DE = 0
```

然后切换到接收状态。

必须注意：

不能在 HAL_UART_Transmit 返回以后立即把 DE 拉低。

应该确认：

```text
TC
Transmission Complete
```

真正完成。

例如：

```c
while (__HAL_UART_GET_FLAG(&RS485_UART, UART_FLAG_TC) == RESET);
```

再切回接收模式。

封装：

```c
void RS485_SetTxMode(void);
void RS485_SetRxMode(void);
```

# 七、PC ↔ STM32 自定义协议

PC 不直接发送 Modbus。

PC 使用自定义协议。

建议协议：

```text
Byte 0      0xAA

Byte 1      0x55

Byte 2      Length

Byte 3      Device ID

Byte 4      Command

Byte 5      Parameter High

Byte 6      Parameter Low

Byte 7...   Data

最后2字节：

CRC16 Low
CRC16 High
```

帧结构：

```text
AA 55 LEN DEV CMD PARAM_H PARAM_L DATA... CRC_L CRC_H
```

# 十、PA 参数定义

上位机发送：

```text
PA21
```

在通信协议中发送数字：

```text
21
```

STM32 根据：

```text
PA编号
```

转换成 P100S Modbus 寄存器地址。

规则：

```text
PA n
→ 0x0000 + n
```

例如：

```text
PA1
→ 0x0001

PA21
→ 0x0015

PA53
→ 0x0035

PA71
→ 0x0047
```

封装：

```c
uint16_t P100S_PA_ToRegister(uint16_t pa_number);
```

例如：

```c
uint16_t P100S_PA_ToRegister(uint16_t pa_number)
{
    return pa_number;
}
```

不要让上位机直接处理 Modbus 地址。

# 十三、Modbus 0x06

写单寄存器格式：

```text
Slave ID

06

Address High

Address Low

Data High

Data Low

CRC Low

CRC High
```

例如：

```text
Motor 1

PA21 = 60
```

对应：

```text
Slave ID = 1

Function = 0x06

Address = 0x0015

Value = 0x003C
```

生成：

```text
01 06 00 15 00 3C CRC_L CRC_H
```

然后：

```text
RS485发送

等待P100S响应
```

正常情况下 P100S 返回：

```text
01 06 00 15 00 3C CRC
```

STM32 必须检查：

```text
Slave ID

Function

Address

Value

CRC
```

全部正确才判定成功。

# 二十二、双伺服控制

RS485 是共享总线。

禁止同时给两台 P100S 发送命令。

流程必须：

```text
发送 Motor1

等待回复

解析回复

完成


然后


发送 Motor2

等待回复

解析回复

完成
```

必须实现：

```text
BUSY
```

状态。

例如：

```c
typedef enum
{
    MODBUS_IDLE,

    MODBUS_TX,

    MODBUS_WAIT_RESPONSE,

    MODBUS_PROCESS_RESPONSE

} ModbusState_t;
```

同一时间只能有一个 Modbus Transaction。

# 三十九、开发优先级

请不要一开始实现所有后续功能。

第一版只保证这条通信链路稳定：

```text
PC
↓
UART
↓
STM32H743
↓
协议解析
↓
Modbus RTU
↓
RS485
↓
P100S Motor1 / Motor2
↓
读取PA
修改PA
↓
结果返回PC
```

第一版重点是：

```text
通信可靠性

协议解析可靠性

CRC

超时

双电机地址区分

PA读写
```

等这一阶段稳定以后，再增加运动控制和自动检测功能。

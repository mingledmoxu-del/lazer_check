## 连接

| 项目 | 默认值 |
| --- | --- |
| 开发板静态 IPv4 | 192.168.10.50 |
| 子网掩码 | 255.255.255.0 |
| TCP 服务端口 | 5000 |
| 电脑连接开发板的网卡示例 | 192.168.10.10 / 255.255.255.0 |
| 通信方式 | 单客户端 TCP 字节流，沿用原二进制协议和 CRC |

1. 烧录 `output/firmware/v3.7-main-ethernet-h7/LightCheck.hex`（或 ELF）。BIN 起始地址仍为 **0x08000000**。首次检查时关闭驱动器外部 SON。
2. 用网线连接电脑网卡与板上**主网口**，也可经交换机连接。电脑对应网卡手动设置到同一网段，示例地址如上；直连场景无需填写网关。确认局域网没有另一台设备使用相同地址。
3. 可先在电脑执行 `ping 192.168.10.50` 检查链路及 IP 通信，再执行 `Test-NetConnection 192.168.10.50 -Port 5000` 检查 TCP 监听。端口检查会短暂占用一个连接，关闭后固件会请求停止两轴，等停止确认后再连接上位机。
4. 启动 `app/start_simple.bat`，连接方式默认“TCP网口”，IP填 `192.168.10.50`、端口填 `5000`，点击连接。只连接不使能、不运动；先读取 PA11、报警、位置与 DI 输入。
5. 按 v3.6 说明重新应用电机1双限位配置：水平侧 DI2、抬头侧 DI0，填写实际触发电平、方向和两个实测角度。烧录/复位会丢失 RAM 配置；单纯断开 TCP 不会主动清除已有且仍有效的角度参考。

上位机的 IP/端口输入只选择连接目标，不会远程修改开发板 IP。要修改板端地址，编辑 `LightCheck/Network/Inc/network_config.h` 并重新编译。

## 断开和重连

固件只接受一个控制客户端。已有客户端或两轴仍在停机确认中时，新连接会关闭，不能通过第二个连接绕过停机。

检测到网线链路下降、TCP FIN/RST/错误、发送失败或 TCP 保活失败后，清空该会话未执行的接收字节和半帧，取消回零/轨迹，并对**两轴**锁存停止请求。普通定角运动也包含在内；停止通信失败会继续重试，直到读回实际转速0。停止确认前不接受新控制会话。

重连必须人工操作。固件和上位机不自动重发运动命令、不自动恢复旧运动或启动旧轨迹；通信中断时，已发出的命令是否执行仍可能未知，应先读反馈。

链路约每250ms检查一次，前台 Modbus 事务会增加检测延迟。对于链路仍显示连接但电脑消失等情况，启用 TCP 保活，空闲3秒后按1秒间隔探测、最多3次，检测时间约6秒并叠加轮询/协议定时误差。原有回零/连续旋转5秒租约与轨迹租约继续独立生效。网络停机需要通信和减速时间，不代替硬件急停。

## 固件结构

- `Network/Src/ethernet_port.c`：RMII GPIO、PB12 PHY复位、PHY地址扫描、10/100M自动协商、HAL ETH 收发。
- `Network/Src/network.c`：lwIP NO_SYS 主循环轮询、TCP单会话、缓冲、断线处理。每轮最多接收4个以太网帧，再让出前台执行电机任务。
- `Network/Src/pc_comm_net.c`：复用原 PC 协议的网络传输适配。双限位、角度、轨迹和电机协议均不改帧格式。
- `.eth_dma`：D2 SRAM 中的32字节对齐描述符与收发缓冲；MPU把前256KB D2 SRAM映射为不可缓存。lwIP的普通堆和控制结构位于DTCM，不被直接交给ETH DMA。

网口引脚为 PA1/PA2/PA7、PC1/PC4/PC5、PG11/PG13/PG14，PHY复位 PB12。电机总线仍为 USART3 PC10/PC11、方向控制 PC12；DI0～DI5仍为 PF5～PF0。网口固件不初始化 USART1，避免依赖损坏的 USB 转串口通道。

默认 CMake `PC_ETHERNET=ON`，常规 Debug 构建生成主网口固件。配置 `-DPC_ETHERNET=OFF` 可编译 UART1 备用版本；上位机选择“串口”时须搭配串口固件，当前网口固件不同时接受串口控制。

这是 CMake 手工适配网络工程；原 `.ioc` 尚不包含本次网络配置。不要直接用旧 `.ioc` 重新生成并覆盖已适配的 HAL配置/主程序后就烧录。

## SDK

```python
from app import MotorController

motors = MotorController("tcp://192.168.10.50:5000", timeout=2).connect()
print(motors.read_pa(1, 11))
print(motors.get_axis1_limits())
# 双限位、回零、定位等 API 沿用 v3.6。
motors.close()
```

TCP 使用标准库 socket；原 COM 串口方式仍通过 pyserial。SDK一旦遇到通信结果不确定会拦截后续请求，需明确关闭并重连，不会自动重试运动。

## 验证边界

已验证 H7 网口和 UART1 备用配置编译、业务回归、真实本机 TCP 的 SDK收发/拆包/断开、实际 lwIP 原始TCP会话逻辑下的单客户端、粘包、断线停止、失败应答后的剩余指令拦截及链路丢失；另做上位机GUI连接/断开检查和固件 HEX/BIN校验。

**尚未在这块实物 H7 板上验证 PHY、网线和电机，也未替用户烧录。** 本机TCP与虚拟网卡测试不能证明实际RMII引脚、PHY协商或电气硬件正常。首次实机先完成第1～4步，只读验证后再进行限位和低速运动验证。

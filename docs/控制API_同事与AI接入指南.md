v3.8.6当前行为：0x19及API签名不变，末段速度不再按“剩余距离×固定比例”无限降低，改为满足反应距离+制动距离的最大允许转速，并受请求速度上限约束。每次定位读取实际PA41、PA42建模（不修改参数）；PA41单位是电机1000→0rpm所需ms，PA42作为额外距离余量。保留到位容差、两次零速、超调先停再修正和异常保护。单位参数由每周期重复读改为最多每秒复查，位置每次控制仍实读；新鲜的控制采样可供PC反馈查询复用，READ_AXES标记来源及样本年龄，过期后重新实读。

停稳延迟优化：SDK `move_to_angle()`不再嵌套调用会重复停止的`move_relative()`；`reset_axis1()`有参考时复用同一操作刚完成的停止与反馈，单次操作只做一轮停止确认。不跨调用缓存“已停稳”。`stop()`仍连续实读两次零速，采样间隔由100ms改20ms；GUI停止复查由120～150ms改20ms，去掉确认后80ms固定等待。固件对原本零速的轴不重复写停止，速度模式已经为0的速度组/已选中的速度源仅读回、不重复写入。运动中界面两轴位置请求间隔200ms、调试反馈250ms；实际周期受通信与调度影响，不能承诺20ms完成停稳。

调用建议：坐标定位直接调用一次`move_to_angle()`或`move_to_zero()`，它们已经包含必要的停止确认；无须再额外嵌套stop循环。上层业务若自行在每个点后等待停稳、停稳后再次stop，仍会产生调用方附加等待。本版不改变外部调用方代码。模拟测试不能证明现场动态性能；需测量调用开始/应答/实际停稳/下一动作开始时间。

v3.8.5当前定位路径：GUI和SDK的`move_relative()`、`move_to_angle()`、已有参考时`reset_axis1()`及`move_to_zero()`都使用新命令0x19，parameter=0x5054（PT），payload仍为大端uint16速度×100 + int32输出角度×1000，应答返回接收的有符号相对角度。旧固件会拒绝，不回退旧0x14。新版固件保留0x14兼容诊断旧路径，但日常业务不要调用它。

板端取消同轴旧追踪目标、停止并确认两次零速，从实际停稳位置计算新目标。使用带符号内部速度与编码器反馈每50ms调度控制，接近目标时比例减速，微小越过目标会先制动再修正，容差PA11/200+1计数（默认约0.037°输出轴）。完成后速度设0，两次零速确认后结束任务。无需普通换向后手动清故障；停止与任务替换保留参考。通信失败、反馈单位变化、真实反向、3秒无进展、超时、驱动报警及限位仍触发停止保护，不无条件重发或强行运动。新点位任务期间先停止再改参考、配置、运动曲线或启动双轴轨迹。速度设定÷6和网口连接API不变。

这是一条新增控制路径，主机模拟回归与构建不能证明真实驱动器动态响应或定位精度；请先低速小角度验证换向、减速、到位和停止，再用于完整行程。

v3.8.4补充：针对停止后换向仍沿旧方向的问题，P4位置参数逐项写入并读回；P4-1改为20ms，CTRG低电平保持期间等待60ms并复查零速，然后同一写入释放HOLD并触发CTRG。主循环在定位启动后前3秒每100ms检查原始编码器方向，方向相反超过PA11/1000+2计数或3秒无可测位移时，请求停止并锁存单轴fault=8。应答成功只代表提交成功，不等于驱动器执行/到位成功；应用必须继续读反馈或使用阻塞到位API。此版本已通过模拟测试和H7构建，驱动器实际触发接纳与换向仍待现场验证，60ms延时不等同于读到CMDOK。

fault=8不清除有效坐标，不自动重发启动。原因处理后，GUI“电机1复位/位置状态”窗口点“清除执行故障”，或SDK调用`clear_guard_fault(1)`；固件复查两次零速、报警、参考与软范围，仅清故障，后续运动必须另行明确发起。新增线协议：`0x21 / parameter=4 / 空payload`，仅确认fault=8，兼容电机1双限位。通信故障仍按既有规则使参考失效。此监测是启动阶段检查，不替代全程到位判断、机械限位或硬件急停。

v3.8.1补充：修复首次无参考时刷新反馈被误判为反馈单位变化、反复停机的错误。首次操作无需先清坐标；有参考时普通回35°继续保留参考。GUI新增“清除电机1参考”，SDK新增`clear_axis1_reference()`，仅在明确需要重新标定时使用。

v3.8.2速度变更：复位/回0高层API和GUI输入统一除6，低层`move_to_angle`、`move_relative`的speed_rpm仍表示真实rpm。后者若需相同速度，应由调用方显式传设定值/6。很慢的0.2设定从水平找DI0可能超出固件120秒搜索上限，不建议用于首次全程搜索；默认0.6或0.5适用。

## 1. 环境、连接与单位

- 项目根目录加入 Python 搜索路径，从 `app` 导入；Python 3.10+，依赖见 `app/requirements.txt`。SDK 不创建 Tkinter 窗口。
- H743 主网口 CN2，板端固定 `192.168.10.50:5000`。电脑有线接口可设 `192.168.10.10/24`，直连不填默认网关；Wi-Fi 可继续上网。
- 一块板只允许一个主客户端。运行 SDK 前断开 GUI；不要由两个程序同时控制。
- **本篇高层 API 的 speed_rpm 保留旧参数名，但从v3.8.2起是速度设定值，实际输出轴rpm = speed_rpm / 6**。默认设定 **0.6**，闭区间 **[0.2, 1.5]**。设定0.6实际0.1rpm（0.6°/秒）；设定0.5实际约0.0833rpm（0.5°/秒）；设定1.5实际0.25rpm（1.5°/秒）。SDK/STM32按50:1换算为电机转速。不要自行先除6后再传高层API，否则会重复缩放。
- 没传速度参数使用0.6；显式传 `None`、布尔、字符串、NaN、无穷或越界速度会抛 `ValueError`。低层历史API可能保留自己的默认值和单位，不能套用本篇默认规则。
- H743 与两台驱动器之间仍是 RS485、115200、8N2；网口只是替换电脑到板子的通信。

## 2. 机械坐标与参考生命周期

| 项目 | 目前约定 |
|---|---|
| 电机1真实水平 | 0° |
| 电机1抬头限位 | DI0 / PF5，+35° |
| 电机1低头侧限位 | DI2 / PF3，−29° |
| 两路 MCU 输入 | 未触发1，触发0，即低电平触发；与传感器端“高电平输出”区分 |
| 电机1物理角度方向 | 正角度抬头、负角度低头；驱动器原始反向才是抬头，由固件转换 |
| 电机2零位 | 操作者明确确认当前位置为0°；没有假定电机2限位接线 |
| 电机1目标范围 | −29°～+35° |
| 电机1边界反馈容差 | 0.05°，仅供端点反馈检查；目标范围没有扩大 |

参考保存在板端RAM，用编码器当前位置加参考偏移计算角度。普通停止、GUI关闭、网络重连、再次回到35°或0°不主动清除已有效的参考。板子掉电/复位、明确重新标定、重新配置限位或反馈单位异常会使参考失效。程序每次从板端读取有效位，不根据“上次调用成功”推断当前状态。

电机1首次搜索需要从接近水平、两只限位均未触发处开始。DI0触发后先停止，再连续确认零速、传感器仍有效及反馈单位一致，才把停稳编码器位置标为+35°。不是硬件触发瞬间位置锁存；提高搜索速度会改变减速距离，应结合当前机械余量复核停稳角度，不把35°参考当作更高精度的触发锁存。软件停止不能替代硬件急停。

## 3. 推荐高层 API

类：`app.MotorController`。以下接口都是实例方法。`reset_axis1`、`reset_axis2`、`move_to_zero` 是**同步阻塞**调用，等到完成才返回；GUI/服务可放在自己管理的工作线程。一次只调度同一轴的一个复合动作，不并发执行两个运动流程。

| 签名 | 行为与返回 |
|---|---|
| `reset_axis1(*, speed_rpm=0.6, timeout_s=120)` | 有参考：直接按现有坐标回+35°，不重新配置、不清参考；已在35°±0.05°内则不运动。无参考：配置DI2/DI0、低电平、方向和角度，再反向搜索DI0并等待标定。返回 `PositionFeedback`。 |
| `reset_axis2(*, speed_rpm=0.6, timeout_s=120)` | 按电机2既有参考回0°。未建立参考时报错；不会把任意当前位置自动置零，也不寻找未知限位。返回 `PositionFeedback`。 |
| `clear_axis1_reference()` | 显式停止并清除电机1角度参考/旧轨迹，读回反馈；不启动搜索或定位，不把当前位置定义为0°。清除后需调用reset_axis1重新建立参考。 |
| `confirm_axis2_zero()` | 先停稳，明确将电机2当前位置确认为0°，读回校验。没有定位运动；会重新定义电机2坐标并作废旧轨迹。返回 `PositionFeedback`。仅在操作者确认该位置就是零位时调用。 |
| `move_to_zero(motor_id, *, speed_rpm=0.6, timeout_s=120)` | 电机1或2按已有坐标回0°。无参考拒绝，绝不以置零代替运动。返回 `PositionFeedback`。 |
| `wait_for_angle(motor_id, angle_deg, *, timeout_s=120, tolerance_deg=0.1)` | 不启动运动。等待连续两次实际角度在容差内、零速且无停机待确认。返回 `PositionFeedback`。参考失效/保护故障或超时会请求停止并报错，不重发动作。 |

电机2明确提供两种不同操作：`reset_axis2()` 是回到老零位，`confirm_axis2_zero()` 是把当前点定义为新零位。**不要在每次复位前调用确认零位；那会改变坐标系。**

`timeout_s` 必须是有限正数，是高层等待阶段的上限，不包含前面的通信、停止确认和配置耗时。电机1首次限位搜索固件超时上限120秒、行程预算45°；从接近水平出发适用，不用于从整个行程的任意点盲搜。默认设定0.6从0到35°理想运动时间约58秒，加上加减速与通信会更久。

## 4. 可直接调用的示例

从项目根目录执行，先关闭或断开GUI：

```python
from app import MotorController

controller = MotorController("tcp://192.168.10.50:5000", timeout=2.0).connect()
try:
    # 参考有效时只定位；首次无参考才搜DI0。省略速度=0.6输出轴rpm。
    f = controller.reset_axis1()
    print("电机1抬头位置:", f.output_angle_deg)

    # 停稳后回水平，独立指定速度。
    f = controller.move_to_zero(1, speed_rpm=0.8)
    print("电机1水平位置:", f.output_angle_deg)

    # 前提：电机2在本次板子上电后已确认过零位。
    f = controller.reset_axis2(speed_rpm=0.4)
    print("电机2零位:", f.output_angle_deg)
finally:
    controller.close()  # 默认请求两轴停止；通信失败时可能抛异常。
```

电机2首次确认零位，应作为独立、明确授权的操作：

```python
# 操作者已经把电机2摆到希望定义的零点，并明确确认：
f = controller.confirm_axis2_zero()
assert f.output_angle_deg == 0
# 后续回零只调用 reset_axis2()，无需重复confirm。
```

```python
# 查询，不重新配置、不运动：
f = controller.get_feedback(1)
print(f.output_angle_deg, f.motor_rpm, f.home_phase, f.fault)
print(controller.get_axis1_limits())

# 停止：保留已有有效参考；首次搜索尚未建立参考时不会凭空产生参考。
controller.stop(1)   # 默认等待连续两次零速
controller.stop(2)

# 数据传给其他进程/AI，dataclass可转字典：
from dataclasses import asdict
payload = asdict(controller.get_feedback(1))
```

## 5. PositionFeedback 和错误处理

| 字段 | 含义 |
|---|---|
| `output_angle_deg` | 编码器计算的实际输出角度；无可信参考时为 `None` |
| `motor_rpm` | **电机轴**实测rpm，不是输出轴rpm；按50:1换算 |
| `flags & 1` | 参考有效 |
| `flags & 2` | 软范围启用 |
| `flags & 16` | 停机待确认 |
| `home_phase` | 0空闲，1～6回零过程，7回零完成，8回零失败。普通回到35°是定位，不要求phase=7。 |
| `fault` | 0无，1传感器，2软范围越界/搜索超行程，3反馈单位或计数异常，4超时/心跳，5驱动通信，6驱动报警，7取消 |
| `raw_inputs` | 六路MCU实际电平位图：bit0=DI0，bit2=DI2 |
| `active_inputs` | 按板端实际配置判定后的有效输入位图；未配置时不要仅据此推断接线 |
| `actual_counts` / `origin_counts` | 实际编码器计数 / 建参考时的计数 |

调用失败应处理异常：`ValueError` 参数非法；`CommandRejected` 板端拒绝（检查status和反馈）；`CommunicationError` 通信不确定；`DriveAlarm` 驱动报警；`MotorError` 其他状态错误。不要自动重发运动来试错，不要把 `confirm_axis2_zero()` 或 `set_current_angle()` 当成通用清故障。

普通定位可从另一个受控线程调用 `stop(axis)` 取消：等待接口检测到停止版本变化会报取消，保留参考。请求停止不保证瞬间到位。首次限位搜索的心跳由SDK自动续期，等待应使用SDK方法，不自行关闭续期线程。重连后重新读板端参考再决定动作。

## 6. 其他已暴露能力与底层接口边界

| 方法 | 用途 / 注意事项 |
|---|---|
| `get_feedback(id)`, `get_current_angle(id)`, `get_axis_positions()` | 单轴详细反馈、可信角度、两轴位置快照 |
| `get_axis1_limits()`, `get_guard_config(id)` | 读取限位配置与软范围 |
| `move_to_angle(id, angle_deg, speed_rpm=...)` | 任意坐标定位，返回的是接收结果 `MotionAccepted`，**不等待完成**；需再 `wait_for_angle()`。历史默认速度0.2rpm，不是本篇高层默认。 |
| `move_relative(id, angle_deg, speed_rpm=...)` | 相对角度运动，同样不等待完成。电机1按物理抬头为正。 |
| `stop(id, wait=True, timeout=10)` | 普通停止并确认；`close(stop=True)` 默认请求两轴停止 |
| `read_alarm(id)`, `reset_alarm(id)` | 驱动报警读取/复位，不重建坐标 |
| `get_fault_report(...)`, `clear_guard_fault(id)` | 故障分析/显式清保护故障，具体约束见故障处理文档 |
| `set_motion_profile(...)` | 驱动内部加减速参数，毫秒；与输出轴速度不同 |
| 轨迹接口 | 原两轴上传、准备、启动、停止、查询、等待接口保留，见两轴轨迹文档；轨迹起点要匹配当前参考与位置。 |

以下是**显式重新配置/重新标定的低层API**，AI不应拿它们实现日常reset：`configure_axis1_limits()` 会清旧参考；`home_axis1_raised()` 是旧的强制重新标定组合；`start_axis1_limit_homing()` 是直接限位搜索；`set_current_angle()` / `set_current_zero()` / `set_current_reference()` 会改变参考；旧电机1+25°入口不适用于当前双限位业务。`speed_deg_s` 命名明确表示°/秒，与新版 `speed_rpm` 不同。

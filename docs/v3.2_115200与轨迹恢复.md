# v3.2：115200、实际位置与轨迹恢复

> 当前v3.3已进一步简化日常业务，并允许电机2在参考有效时无软范围运行。参考建立、固定电机1范围和日常入口请以[v3.3说明](v3.3_日常业务操作.md)为准；本文保留v3.2协议、时序和历史升级说明。

本版必须同时更新STM32固件与上位机/API。两台驱动器PA72=1152、PA73=0，保存并复位；PC串口仍为115200/8N1，驱动器总线改为115200/8N2。没有自动写入驱动器PA72、修改SON或重新置零。旧9600固件不能与已切换115200的驱动器通信，包括通信停止。

## 现场升级顺序

1. 保持两轴停稳、外部SON关闭。确认两台驱动器已保存PA72=1152、PA73=0。
2. 烧录`LightCheck/build/Debug/LightCheck.elf`（或交付目录中的同版本HEX）。驱动器重新上电，SON仍保持关闭。
3. 用新版上位机连接PC串口。先查询两轴报警、转速、PA72和PA73；应能返回两轴数据，PA72=1152、PA73=0。若任一轴无应答，不恢复SON，核对地址1/2、波特率、格式和RS485接线。
4. 重新建立真实参考并启用已核实的软范围。电机1人工参考只能在真实+25°姿态执行；电机2在所需0°位置建立参考。角度无效显示为未知，不是0°。
5. 检查界面“实际位置”：两轴角度与机械姿态一致、零速、无报警且反馈持续更新。再恢复外部SON，先做小幅、慢速测试；记录误差和实际周期，再逐步增加轨迹要求。

SDK检查通信参数：`motors.read_pa(1, 72)`和`motors.read_pa(2, 72)`均应为1152；将72换成73均应为0。现有GUI“关键参数检查”不等同于此通信参数核对，不能仅凭该按钮认定PA72正确。

## 运行及故障后的实际位置

新增命令0x37（设备1，parameter=0，无请求数据），一次返回两轴位置。运行和停止确认期间复用控制反馈，不额外占用RS485；任务结束后重新读驱动器。轨迹0x34仍保留故障快照，不把它当作此刻位置。

响应40字节，两轴各20字节，均大端：`int32 angle_mdeg, int32 counts, int16 rpm, uint16 flags, uint32 age_ms, uint16 alarm, uint8 guard_fault, uint8 source`。flags的bit0=角度参考有效、bit1=软范围开、bit2=硬策略开、bit4=停止处理中；source=0驱动器新读、1控制缓存、2读取失败。年龄从驱动器状态应答完成计时，非编码器硬件采样时间；两轴顺序采样，非同时采样。读取失败age=0xFFFFFFFF，旧数值不能使用。

API `get_axis_positions()`返回两个`AxisPosition`，`angle_deg=None`代表参考或读取无效；`usable`要求角度有效且采样年龄≤1000ms。UI窗口打开时约每秒更新实际位置；运行仍优先续期，3秒未收到更新会显示未知。读取有效不代表机械路径已被验证。

```python
positions = motors.get_axis_positions()
for axis, p in enumerate(positions, 1):
    print(axis, p.angle_deg, p.motor_rpm, p.sample_age_ms, p.usable)
```

## 两轴共同减速

普通GUI默认勾选共同减速、控制周期100ms；API保留固定时间默认值，明确传`adaptive=True`启用。新固件允许50～500ms；50ms是否能稳定运行必须看实测通信耗时，不能把设置值当作实测性能。建议先用100ms。

```python
ready = motors.prepare_trajectory(
    points, cycle_ms=100, max_speed=1.5, max_accel=3,
    max_error=0.75, tolerance=0.3, adaptive=True,
)
motors.start_trajectory(ready.session)
motors.wait_trajectory(ready.session)
```

两轴反馈先采集，再推进同一个路径进度。任一轴误差达到最大误差的1/4后降低推进速率，达到3/4时暂停路径进度并继续位置纠偏；候选下一目标也被限制在两轴可跟随范围内。速度前馈按同一个推进比例缩放，不能让其中一轴独立赶时间。严重误差超过`max_error`仍立即停机，限位、通信、报警、心跳和调度保护保留。总墙钟时间超过计划时长×4+30秒时以故障13“路径推进超时”停止，避免堵转后永久等待；终点收敛最多5秒。

共同减速模式中的`elapsed_s`是路径计划进度，不是实际运行秒数；程序需要精确固定圈时就使用`adaptive=False`并验证设备能跟上。默认`wait_trajectory(timeout=None)`按计划时长×4+35秒设置调用方等待期限；显式timeout仍有效。未放宽现有最大误差，不保证固定圈时、末端圆形精度或实物跟随效果。

协议BEGIN长度仍为20字节，cycle字段bit15表示adaptive，低15位是毫秒。旧固件会拒绝高位标志或小于250ms周期，不会静默降级。其他轨迹报文保持兼容。

## 故障后准备回首点

故障7不会自动清除可信参考；不要用重新置零隐藏误差。故障0x34快照保留，0x37独立更新停稳后实际位置。通信或参考故障可能使参考无效，此时禁止自动返回，必须先核查。

GUI：停止两轴并等停稳 → “准备回首点（不启动）” → 读取实际位置和软范围 → 确认整个返回路径安全 → 上传校验 → 单独点击“启动已校验轨迹”。返回完成后点击“恢复原轨迹草稿”，再重新上传并启动。原会话不会恢复或重播。停止、断线、拒绝确认和准备期间修改参数都不会触发延迟启动。

API：

```python
# original_points由调用方保存，必须与当前参考坐标一致。
# 调用前确认到原首点的关节角路径、机构及线缆安全。
ready = motors.prepare_return_to_start(original_points)
# 上一行只停止、读取和预载，不启动；这里是调用方明确批准运动的边界。
motors.start_trajectory(ready.session)
motors.wait_trajectory(ready.session)
# 返回完毕后重新prepare_trajectory(original_points, ...)，再启动。
```

返回使用17点平滑关节角路径，默认速度上限1.5°/s、加速度3°/s²、最大误差0.75°、容差0.3°、共同减速；时长按位移保守生成，至少2秒。它不是沿原圆倒退，软件软范围不能检测空间障碍物。两轴必须零速、有可信参考、软范围开启、无驱动/保护故障；采样过期或读取失败会拒绝。首尾均须距软边界至少1°，完整路径仍由固件校验，不能通过本接口扩大范围。

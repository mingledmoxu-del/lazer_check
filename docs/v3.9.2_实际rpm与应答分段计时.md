# v3.9.2：实际输出轴 rpm 与应答耗时

本版上位机与 H743 固件应配套更新。SDK 协议兼容 v3.9.1；本版没有重新定义速度参数的线缆单位。未进行本版实机运动测试，不能把测试通过当成已达到 1 秒。

## 速度操作

「两轴联动计时 / 固定点位预载」直接填写**实际输出轴 rpm**，取消旧页 0.2～1.5 的设定范围及除以 6 的换算。允许 0.01～100 rpm（当前减速比 50:1 对应电机命令最高 5000 rpm）。这只是协议可表达的命令范围，不是已验证的整机最高运行速度；实际还受驱动器能力、制动距离、控制采样和负载影响。板端仍检查减速比换算后的速度。

默认值 0.1 rpm，保持旧版填写 0.6 时的实际速度。1 rpm＝6°/秒；新版填 0.6 就是实际 0.6 rpm，是旧版填 0.6 时的六倍。速度只能影响下一次运动；修改预载速度后必须重新上传库，旧库不会自动改速。复位/寻限位窗口的旧速度设定规则没有在本次修改，仍按该窗口提示操作。

SDK `move_axes_to(..., speed_rpm=...)`、`preload_route(..., speed_rpm=...)` 原本就是真实输出轴 rpm，调用方不要再除以 6。预载后按编号运行仍采用上传时的速度与容差。

```python
# 已连接 tcp://192.168.10.50:5000，已完成两轴参考与停稳。
route = controller.preload_route(
    [(0, 0), (6.9, 0), (16.1, -9.7), (24.8, 0), (16.1, 9.7), (0, 0)],
    route_id=1, speed_rpm=1.0, tolerance_deg=0.2,
)
# 上传不运动；由业务事件单独触发一个点。
result = controller.move_preloaded_point_and_wait(1, 1)
# 复用 result['positions']，无需再停止或重复本轮完成核验。
print(result['accepted_ms'], result['wait_ms'], result['elapsed_ms'])
```

## 应答前优化与计时

点位准备复用**本次实际状态包**内的 0x1009 控制模式，不再单读一次。速度源 PA22 与速度命令 PA24 合并为一次连续读取；如驱动器明确拒绝这个范围，只回退读取这两个端点。超时或 CRC 错误不会隐式重试，更不会重发运动写入。常规速度模式已准备好的路径，两轴合计减少 4 次 RS485 读取；未缓存旧运行状态，也未省略非零速度、报警、参考及限位检查。冷启动需要重新配置模式时，仍执行写入和核验。

联动计时表增加两列，CSV 和 `JOINT_TIMING` 日志同步增加字段：

| 字段 | 含义 |
| --- | --- |
| `ack` 应答s | 上位机实际发送到收到接受应答 |
| `board_prep` 板端双轴准备s | 应答携带的两轴准备耗时之和；同一段两行显示相同值 |
| `ack_other` 应答其余s | `max(0, ack - board_prep)`；含准备计时之外的板端保护调度、通信及上位机处理，不能直接认定都是网络延迟 |

另记录 `JOINT_ACK_TIMING`：`ack_ms`、`board_axes_ms`（两轴分别计时）、`other_ms`。原来的“准备s”是界面产生本段到实际发送的排队时间，常为 0，不能当作板端准备为 0。SDK 继续用接受应答中的准备耗时及 `accepted_ms` 定位瓶颈。

## 1 秒目标的边界

用户截图旧页填写 0.6，实际 0.1 rpm，即 0.6°/秒；16.1°回程仅匀速运动理论下限约 26.83 秒，与 27.718 秒总耗时相符。提高真实速度会明显缩短这部分。

应答约 0.56～0.72 秒已经小于 1 秒，但还应缩短。截图到位→停稳约 0.78～0.88 秒，含从 ±0.5°观察窗口进入最终 ±0.2°、制动、实际零速采样及主机得知完成的延迟，不能全部视为固定等待。把“应答+末段完成”压到约 1 秒是复测目标；本版仅能确认通信事务减少，不能预先保证目标。

如果要求包括运动在内每段 1 秒，16.1°的纯匀速理论需求就超过 2.68 rpm，且还没有计入准备、加减速和停稳；只放开速度上限不能保证实现。实际以相同路线、相同真实速度、相同容差的 CSV 比较为准。±0.2°、两次实际零速和直接最终完成反馈仍保留；编码器/电机停稳不等于已测得光斑无振动。

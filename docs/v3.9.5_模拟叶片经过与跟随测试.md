# v3.9.5 模拟叶片经过与三点/四点跟随测试

## 目的与版本

这是上位机独立测试窗口：**模拟叶片时间，实际驱动两轴，不调用激光采集**。用于复现测试表中的三点/四点同半径跟随，比较换点耗时、赶点余量与停止瞬间目测抖动。不是激光采集质量验收，也不保证真实叶片命中。

上位机 v3.9.5，固件继续使用 v3.9.4；本次没有修改或重烧固件，没有改变业务采集 API、参考系、限位或完成证明。测试临时占用并覆盖板端 **库6**，其他五套库不变；完成测试后业务层须重新预载自己的库6。不要同时用另一客户端控制同一板子。

## 操作流程

1. 运行 `app/start_simple.bat`，连接 TCP（默认 `192.168.10.50:5000`）或串口；按原流程建立两轴真实参考。
2. 打开主界面「模拟叶片经过 / 三点四点跟随测试」。选择三点或四点、P1～P5其中一圈、模拟每转周期、A/B延迟、实际输出轴rpm、圈数、终点容差。
3. 核对安装几何和角度原点。默认距离2.5m、中心高差0.73m、俯仰原点+0.267°、水平原点+0.234°来自台架测试表，**其中原点是待实物核验值**。60～100m实际工况须修改距离及实测几何，不能直接照搬台架角度。点击「预览路线/时序」检查生成的整圈坐标。
4. 勾选真实参考/路径确认，点击「① 预载并定位起点」。窗口检查两轴新鲜停稳反馈，读取两轴 PA40、PA41、PA42，预载点位到库6，实际运行至点0。这个阶段单独记入JSON，不计入模拟整圈耗时；不会自动清除或建立参考。
5. 状态显示「起点已停稳」后，点击「② 开始模拟 t0」。此刻定义目标叶片进入点0。按绝对时间发送点1→点2→…→点0；多圈重复这条路线，完成后留在点0，末段观察默认0.5秒。
6. 观察停止瞬间机头/安装板/光斑表现，选中表格的某段某轴，选择「无明显 / 轻微 / 明显」并填写备注，点击保存。未填写保持「未观察」，不能算无抖动。可在整圈结束后补填，建议配合有时码的视频。
7. 导出CSV和同名JSON。修改任意测试参数后须先停止、重新准备，不能在已预载路线中混用新速度或新几何。

窗口关闭、主界面停止、参考/反馈失效、故障、通信超时或赶不上模拟时刻均取消剩余路线并请求两轴停止；收到两次有效直接零速反馈后解除占用。停止/超时不会自动继续。断线只能尽力发送停止，实际状态可能未知。

## 路线与模拟时序

P1～P5半径分别为0.16、0.30、0.44、0.58、0.72m。一次只跑其中一圈，不把五个半径串成径向路线。沿从激光器看去的顺时针方向，点0相位为正下方；四点相位0/90/180/270°，三点相位0/120/240°。

对半径 `r`、转子相位 `φ`、距离 `D`、中心高差 `H`：

```text
x = -r*sin(φ)
y = H-r*cos(φ)
pitch = degrees(atan2(y, sqrt(D²+x²))) + pitch_origin
yaw   = degrees(atan2(x, D)) + yaw_origin
```

角度上传精度0.001°。只预载3或4个唯一点，回起点运行索引0，不重复上传终点。

设每转周期 `T`、点数 `N`、点间隔 `I=T/N`。测试表的估计经过宽度 `W5` 为 P1 0.380s、P2 0.170s、P3 0.070s、P4 0.050s、P5 0.030s。改变模拟转速时采用 `W=W5*T/5`，这是保持叶片角宽不变的估计，非实测检测。

```text
A模式发令延迟 d = W + 0.030秒离开确认
B模式发令延迟 d = W + 0.030秒离开确认 + 0.100秒业务处理
第k段（从0编号）：
  计划发令 = t0 + k*I + d
  目的点   = (k+1) % N
  模拟叶片到达目的点 = t0 + (k+1)*I
  该段运动预算 = I-d
```

例如默认四点P3、5s/转、A模式：在 t=0.100、1.350、2.600、3.850s 发令；模拟叶片到点时刻为1.250、2.500、3.750、5.000s。已经完成的段等待下一次**绝对**发令时刻，不以“完成后再等待 I 秒”累积偏移。B模式只是模拟额外100ms业务时间，不执行真实计算或采集。

若在模拟叶片到达时仍未取得两轴完成反馈，记录失败并停止；主机发令调度迟到超过100ms时不发该点，JSON记录漏发原因并停止，不连续补发追赶。即使只迟到少于100ms，发令迟到列也如实记录。Windows/Tk与TCP/串口不是硬实时调度，100ms只是拒绝过期调度的阈值，不是精度承诺。

## 计时与完成判据

沿用当前板端完成证明：两轴真实参考有效、无报警/保护故障，板端已取得两次真实零速，点位完成标志有效、无活动点位/停止待确认，当前直接反馈在配置终点容差内；反馈年龄不大于200ms。运动阶段可用控制缓存观察进度，但缓存不能作为最终完成证明。不会为赶点放宽这个判据。

| CSV字段 | 定义 |
|---|---|
| step / axis / target / tol | 段号、轴号、目的绝对角、完成容差 |
| planned_send / sent_at / blade_at | 相对t0的计划发令、实际发令和模拟叶片到点时刻 |
| send_late | 实际发令减计划发令；包含主机调度/等待当前通信的时间 |
| prep | 本段建立到发令，通常接近0；不包含测试前预载 |
| ack | 发令到下位机应答，接受命令不代表完成 |
| board_prep / ack_other | RUN应答中两轴准备耗时之和；应答耗时扣除板端准备后的其余部分，后者含链路/主机等，非纯网络延迟 |
| start | 发令到首次观测非零转速；无需运动则留空 |
| window / settle | 发令到首次进入±0.5°；首次进入窗口到该轴完成反馈 |
| total / joint_total | 本段建立到该轴完成；到两轴均完成。各阶段多为嵌套时间，不能直接全部相加 |
| margin / verdict | 模拟到点时刻减该轴完成时刻；两轴都非负才算该段赶上模拟叶片 |
| encoder_pp / visual / note | 完成后观察窗口的编码器峰峰角、人工评级与备注 |

所有运动时间是主机**观测时间**，受约30ms GUI调度、最短50ms反馈轮询间隔、下位机及链路耗时影响；实际轮询间隔可能更长。JSON保留原始反馈的观察时刻、反馈年龄、来源、rpm和flags，可分析观测滞后。未及时取得完成证据不等于已经证明真实机械迟到，但不能按通过处理。

准备阶段JSON另含两轴PA配置、预载读回参数、准备/上传耗时、初始定位耗时；上传速度按协议量化到0.01rpm，以 `board_bank_settings` 为准。整圈计时从 t0 开始，JSON的 `elapsed_s` 包含配置的末段观察时间。

## 抖动统计的含义

JSON每行 `encoder_stats` 包含有效样本数、观察跨度、峰峰角 `pp_deg`、相对均值的RMS `rms_deg`、首尾漂移 `drift_deg`、最大目标偏差 `max_error_deg`。统计窗口从**两轴均完成后**到下一段发令前，末段到观察结束；只使用来源为直接反馈且年龄≤200ms的样本。运动/制动过程的原始反馈另外保留，可离线分析。

这是驱动器编码器角度统计，不能测出编码器之后的减速器间隙、安装板弹性振动或光学头/远距离光斑振动。停止瞬间抖动以人工观察或外部视频/传感器补充；“零速”或小峰峰值均不代表光学稳定。样本为0则统计值为空，样本不足2个不能估计峰峰振动幅度。为限制长时间测试内存，原始反馈最多保留最近200000条（丢弃数量写入JSON）；每段每轴统计最多保留最近2000个完成后样本。

建议先固定一种三点/四点、同一P圈和周期，用相同路线对比不同实际rpm或人工调整后的电机1 PA41/PA42。每组保存一份CSV+JSON，比较赶点成功率、最小余量、联动耗时均值/最大值以及“轻微/明显”目测轴次数；窗口不会自动调整驱动器参数。

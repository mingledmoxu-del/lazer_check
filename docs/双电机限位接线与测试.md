# 双电机限位接线与测试

> 本文为历史固定两输入实验方案。v2.0使用新的运行时输入映射和保护策略，见[综合调试与验收](综合调试与验收.md)。旧 `MOTOR_LIMITS_ENABLED` 保持0，串口字符调试关闭；DI0～DI5仍可通过新面板采样和显式启用策略，不能再用旧宏判断实际保护是否启用。下文历史功能不代表当前策略，始终读取下位机实际配置，并保留独立硬件急停。

当前配置：每台电机一个 EE-SX674-WR（NPN，不是带 P 的 PNP 型号），共两个。
板子引脚依据项目内 HYKJN1002-1-D 原理图。以下 DI0、DI1 是板上丝印，DI00、DI01 是原理图网络名。

## 接线（断电操作）

| 板子丝印 | 对应接线 | 原理图位置 / MCU |
| --- | --- | --- |
| DI0 | 电机1限位器黑线 OUT | J7-9 / PF5 |
| DI1 | 电机2限位器黑线 OUT | J7-8 / PF4 |
| ICOM1 | 外部电源 +24V，必须接 | J7-1 |
| 24VIN | 板子供电 +24V | J6-1 |
| 24VGND | 板子供电 0V | J6-2 |

两个传感器都按以下方式连接：棕线接 +24V，蓝线接 0V，粉线接棕线（Light-ON），黑线分别接 DI0、DI1。
板子和传感器使用匹配的 24V 电源与回路；不要把传感器的 24V 信号直接接 MCU 的 PF4/PF5 排针。

在上述接法下：未遮光时传感器输出导通，板上光耦使 MCU 输入为低；遮光、传感器失电或输出线断开时 MCU 输入为高。
软件将高电平视为限位触发。这能检测这些断线情况，但不是安全级断线检测，不能检测所有短路故障。

## 当前功能

- STM32 的 1ms SysTick 采样输入；采到触发立即锁存，输入恢复正常须连续稳定 30ms。
- DI0 只保护电机1，DI1 只保护电机2；未接传感器的轴默认禁止运动。
- 主循环独立处理限位，不依赖上位机持续在线；对应轴发送通信停止命令。
- 停止失败或未确认实际转速为零时，保持运动拦截并间隔 200ms 重试。
- 触发期间禁止该轴正反转、启动和通用 PA 写入；状态读取、停止和报警读取仍可用。
- 限位解除并确认停稳后，需要一条新的运动命令；不会自动恢复上次未完成运动。
- 当前没有正/负端方向配置，不支持触发后带电反向退出限位；不能将单个传感器当作两端完整行程保护，也未实现自动回零。

输入采样快不代表电机能在 1ms 内停止。现有驱动通信为阻塞式 RS485，正在执行的通信、超时和减速都会增加停机距离。传感器应设在机械极限之前，预留足够余量；该功能不能替代独立硬件急停或驱动器硬限位。

## 上位机与协议

重新编译并烧录 `LightCheck` 固件，再启动精简上位机 v1.6。
“检查运行状态”会显示“限位触发/断线”或“限位停机确认中”。完整版上位机也增加了限位状态显示。

- 运动被限位拦截：响应状态 `0x08`。
- 读取转速响应：保留前 4 字节（有符号转速、运行状态），新增第 5 字节限位标志。
- 标志 bit0：输入处于触发状态；bit1：锁存的触发尚未完成停止确认。二者均为 0 才允许新运动。
- v1.7 新增 bit2：该轴处于显式限位调试旁路，忽略 bit0/bit1 的运动拦截；原始输入仍报告。
- `0x16` 限位调试命令：parameter 必须为 `0x4C44`，数据恰好 1 字节，0=恢复保护并请求停止，1=先停稳再开启旁路，2=只续期现有旁路。成功响应的 2 字节无符号数为实际旁路状态（0/1）。
- 旁路有效期 5000ms；只存 RAM，开机默认关闭。上位机每约 1 秒续期，断线/退出/超时后停止续期；过期恢复保护并请求停止，迟到续期不能重新开启。模式按轴独立，不能替代硬件急停。
- 新上位机兼容旧固件的 4 字节响应，但旧固件没有本限位功能。

## 首次测试

1. 固定设备，确保人员离开运动区域并准备好硬件急停；先不发送运动命令。
2. 两个传感器保持未遮光，分别查询电机1、2状态；应没有限位提示。
3. 遮住电机1传感器，查询确认只电机1显示限位；其运动请求应被拒绝。然后对电机2重复。
4. 断电后拔开某个传感器黑线，再上电查询，确认对应轴被禁止。断电恢复接线。
5. 最低实用速度、小角度测试运动中遮光停机，并测量实际停止距离。解除遮光后应保持停止，重新发命令才允许运动。

若正常状态仍提示限位，先检查 ICOM1 是否接 +24V、粉线是否接棕线、型号是否确为 NPN，以及黑线是否接对 DI0/DI1，勿通过屏蔽软件保护来继续试转。

## 串口字符调试（暂时开启）

`LightCheck/Core/Src/main.c` 中 `LIMIT_SERIAL_DEBUG` 默认为 `1`。
重新编译烧录，关闭上位机（串口不能同时被两个程序占用），打开现有 PC 串口的串口助手，设置 **115200 / 8N1 / 无流控 / 文本接收**。
保持电机不使能，先仅遮挡/放开传感器验证输入，不需要发送字符或运动指令。

示例（时间为采样时刻，不是实际发送时刻）：

```text
[LIMIT 1200 ms] M1 DI0 TRIGGER raw=1 active=1 count=1
[LIMIT 1530 ms] M1 DI0 CLEAR raw=0 active=0 count=1
[LIMIT 2000 ms] M2 DI1 TRIGGER raw=1 active=1 count=1
```

`INIT` 是上电输入快照；`raw=0` 表示输入电路导通，`raw=1` 表示遮光/断线/失电。
启动的 `active=1` 是保守的启动拦截，即使 raw=0 也要连续正常 30ms 后才打印 CLEAR。
`TRIGGER` 表示触发，`CLEAR` 表示输入稳定恢复，但不代表电机已经停稳；`count` 是本次开机该轴累计的新触发次数。
持续遮挡只打印一次；再次放开并保持正常至少 30ms 后再遮挡，计数增加。

中断只入队，不发送串口；主循环先处理限位停止，再发送一条调试信息。队列满会打印 `WARNING dropped=...`，不是无限缓存。
通信阻塞时字符可能延迟输出；调试串口发送本身也最多阻塞 20ms，因此只用于验证输入。
普通上位机不会把这些文本显示为协议日志。测完建议将 `LIMIT_SERIAL_DEBUG` 改为 `0` 并重新烧录，恢复纯二进制串口。

## 自动测试

`LightCheck/tests/test_limits.c` 使用模拟驱动器验证启动拦截、释放去抖、短触发锁存、停止失败重试、停稳确认、两轴隔离、配置中途触发和禁止自动续跑。
这是主机侧逻辑测试，不替代固件目标编译和实机接线、停机距离测试。

`LightCheck/tests/test_limit_debug.c` 验证触发/解除字符、独立轴标签、计数、不连续刷屏、ISR 不发送以及队列溢出提示。

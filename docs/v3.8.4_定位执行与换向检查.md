# v3.8.4：停止后换向与定位执行检查

日志证据：17:55:16下发−5°；17:55:19停止并读到零速；17:55:20下发+5°且应答正确，但电机仍为+9rpm、物理角度继续减小。因此不能归为GUI符号错误，SDK通过相同固件路径也会受影响。

P100S第39版手册P4-1说明：参数为0时按ZSPD重新接纳触发；非0时，位置命令完成或停止后延时输出CMDOK，再接纳CTRG。HOLD是暂停，不能把零速或写入成功当作旧任务已被替换的证明。

## 本次修改

- P4-1设20ms；模式、圈数、余脉冲、速度逐项写后读回。读回不符不触发。
- CTRG拉低后读回P3-18，等待60ms并再次确认零速；同一事务释放HOLD及置CTRG。触发应答丢失时请求暂停，禁止自动重放。
- 每次点位命令，启动后的前3秒以100ms间隔读取原始位置，按原始脉冲目标方向校验，不混淆电机1的物理角度符号反转。反向超过噪声阈值（PA11/1000+2计数）、3秒无可测位移时，锁存GUARD_EXECUTION=8并请求停止；停止失败由保护任务继续请求停止。通信读取失败使用GUARD_COMM，参考按原规则失效。
- 普通停止取消该次启动检查。执行故障保留有效参考，阻止再次点动；不自动重试、不重新设零。
- GUI显示故障原因，新增“清除执行故障”；SDK的`clear_guard_fault()`对fault=8发送明确确认命令并读回。线协议0x21参数4空payload，仅清执行故障，复查两次零速、报警、参考和范围。清除不发运动、不改变保护配置。
- 保留v3.8.3的GUI回调代次隔离、停止后两次零速确认；保留速度设定÷6。

## 现场验证

本次无需修改接线，需烧录`LightCheck.hex`并重启新版上位机。板子复位后重新寻找DI0建立+35°参考，回到0°。先在行程中间测试：小角度向一边运动，中途停止，待确认停稳，再发相反方向小角度命令，核对编码器与实际机构方向。不要在两端极限位置做首次换向测试。

若报“定位执行异常”，记录停止前后完整TX/RX及反馈；处理原因后先停止，再点“清除执行故障”。不能靠循环清除及重发绕过问题。

已验证：11组C主机测试（含旧任务错误续跑、3秒不启动、参数读回不符、触发应答丢失、确认故障保留参考、协议长度），176项Python测试，H743 Debug构建。测试未连接真实驱动器，不能证明真实P100S触发已经稳定；60ms为等待余量，没有直接读取CMDOK。若仍出现fault=8，下一步需采集驱动器CMDOK/CTRG/HOLD实际状态，不能宣称软件延时已彻底修复驱动器行为。

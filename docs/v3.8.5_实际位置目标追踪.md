# v3.8.5：按实际位置执行最新角度目标

## 改动目的

停止后新方向仍续跑旧P4位置段，不能靠增加延时和让操作员反复清故障解决。新版角度业务改为板端位置追踪，直接用带符号速度控制驱动器，不释放旧P4任务的HOLD，不触发CTRG。

新目标处理：取消同轴旧追踪任务→请求停止→最多等待2秒确认连续两次零速→按实际停止位置计算新相对目标→复核反馈单位与软范围→选择内部速度模式并读回模式/速度源→按目标误差决定正负速度。每50ms调度，临近目标减速；微小超调时先制动再反向修正。到位容差默认约0.037°输出轴，连续两次零速后结束。

普通停止不清坐标，不保留待续跑目标。后续反向命令使用真实停止位置作基准。运行中收到新版相对角度命令，也先取消旧任务并停稳，再执行新目标。SDK和GUI自身的停止确认流程继续保留。

## 协议与兼容性

- 新业务命令0x19；parameter=0x5054；6字节payload：大端uint16真实输出轴rpm×100，加int32物理输出轴相对角度×1000。
- 返回成功表示板端接收任务，返回int32有符号相对角度；到位须看实际反馈或SDK阻塞等待。
- `build_move_output_relative()`、`move_relative()`和`move_to_angle()`函数名保持不变，自动使用0x19。复位、回水平使用这些接口，首次未知参考寻找DI0仍走原速度回零状态机。
- 旧固件拒绝新命令；禁止悄悄回退0x14。必须同时更新固件和上位机/SDK。
- 旧0x14诊断路径保留v3.8.4行为，不是本版本日常运动路径。
- 速度、网络、限位极性和坐标约定不变。高层复位/回0速度设定仍除6，低层speed_rpm仍是真实rpm。

## 保护边界

停止、更换任务、正常减速及微小超调修正不需人工清故障。故障处理仍用于真实的异常：通信失败、反馈单位变更、驱动器实际沿已下发速度反向运动、3秒没有可测进展、控制调度超过1秒、目标执行总时限、驱动报警、限位。停止失败由现有保护任务继续请求停止，不能承诺通信故障下必然立即停住。

新任务不更改SON、电子齿轮、编码器零点或DI映射。速度模式零速用于任务完成后的停止，实际负载下的保持与动态精度需实测；本实现不等同于驱动器内部位置环的整定结果。

## 更新与验收

先烧录本目录LightCheck.hex，再用本目录源码包启动上位机。板子复位后重新建立DI0参考，然后回水平。行程中间低速测试+小角度→中途停止→−小角度，以及相反顺序，确认新目标从实际停止位置计算。再观察0°/35°附近减速与到位，不直接用最高速度测试端点。

验证包括：12组C主机测试、176项Python测试、H743 Debug构建、GUI构造检查。新增模型测试覆盖停止换向、运行中替换任务、实际停止位置基准、到位、微小超调自动修正、停止未成功不启动、通信/单位异常停机；确认不触发旧P4段。测试未连接真实驱动器，必须实测动态响应。

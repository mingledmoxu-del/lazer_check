# v3.9.1：预载点位、按编号触发与±0.2°完成容差

需同时更新H743固件、上位机与SDK。主网口仍为 `192.168.10.50:5000`。本版按用户确认的业务精度，将新双轴定位/预载点的默认最终角度容差设为±0.2°，同时保留实际零速、参考、报警及限位检查。

## v3.9.0实测比较

用户两次截图中，速度设定均1.5，即真实输出轴约0.25rpm。可比较的后两段如下：

| 段 | 旧版联动总耗时s | v3.9.0总耗时s | 减少 |
|---|---:|---:|---:|
| 10°→0° | 8.203 | 7.906 | 0.297s，约3.6% |
| 0°→10° | 8.218 | 7.968 | 0.250s，约3.0% |
| 两段合计 | 16.421 | 15.874 | 0.547s，约3.3% |

两次第一段起点/距离不同，不能直接拿整次18.203s和24.141s判断版本快慢。新版单次ACK包含两轴共同准备，不能与旧版单轴ACK直接比较；旧版第二轴下发间隔约0.5s，新版同一包为0。

这只是用户截图中的一次对比，不是重复试验统计。v3.9.1的新点库及±0.2°策略尚待实机复测，不承诺节省指定秒数。

## 新流程：提前准备，逐点触发

板端有4个独立RAM点位库，编号1～4；每库最多16个两轴绝对点，保存速度和终点容差。先上传、封存校验并准备速度模式，**不启动运动**。使用时只发送“库编号、令牌、点编号”，板子按真实位置前往指定点，停稳后等待下一条指令，不自动跳到下一点。

GUI预设四点路线如下，编号从0开始：

| 点编号 | 电机1/俯仰° | 电机2/水平° | 用途 |
|---|---:|---:|---|
| 0 | 0 | 0 | 开始前的原点坐标 |
| 1 | 6.9 | 0 | 测点1 |
| 2 | 16.1 | −9.7 | 测点2 |
| 3 | 24.8 | 0 | 测点3 |
| 4 | 16.1 | +9.7 | 测点4 |
| 5 | 0 | 0 | 最后返回原点坐标 |

角度来自用户提供的估读表，可在上传前编辑；不是几何标定结果。这里保存的是事件驱动的绝对点位库，运动沿原点到点控制路径执行，不是带时间插补曲线，也不保证两驱动器同一时刻启动。需要指定弯曲路径、绕障或同步插补的应用仍应使用专门的轨迹路径。

RAM内容断电/复位丢失；参考清除/重建、保护配置修改会使预载失效。执行时校验令牌和当前原点、参考角、反馈单位、方向和减速比，不允许把旧参考下的预载当作新坐标使用。新令牌替换同编号库，旧调用会被拒绝。

## ±0.2°策略到底改了什么

- 新双轴 `move_axes_to()`、GUI联动测试及新预载库默认容差为±0.2°；GUI可选0.05°、0.1°、0.2°。SDK/协议显式支持0.01°～0.5°，本项目当前业务默认0.2°。
- 到达允许窗口后进入零速停机阶段，仍需两次独立实际零速且最终编码器位置在允许范围内，才设置板端完成标记0x40。单次零速、ACK、进入±0.5°观测窗口、缓存完成标记都不作为SDK完成证据。
- 末段减速预算与业务完成窗口分开：较大的0.2°不直接从制动距离中扣除，避免放宽了窗口却仍以同样的慢速在窗口外爬行；实际采样周期、PA41/42制动模型与速度写后读回仍保留。更严格的容差会相应收紧制动基准。
- 角度容差换算为编码器计数向下取整，不故意超出业务允许误差。低于编码器分辨率的要求会拒绝。
- 原始单轴0x19/旧版10字节0x1A保持原来的严格完成范围；本版SDK新的双轴默认发送带容差的12字节0x1A。
- 机械限位、软范围、报警、参考有效性、通信和反向检查保持生效。允许±0.2°不表示限位边界也放宽0.2°。

该“完成”证明电机反馈零速及编码器位置符合要求，不能证明结构/光斑已经没有振动。采集软件若有独立的光学稳定性要求，应单独测量；不要把它与电机停机确认混成一个固定延时。

## 上位机操作

1. 烧录同目录v3.9.1 HEX，使用同一包上位机；完成两轴参考建立并停止其他流程。
2. 主窗口点击「两轴联动计时 / 预载固定点位」。
3. 选择「四点测量（含起终原点）」，库编号1，速度设定按需求填写，终点容差默认0.2°。
4. 点击「提前上传点位（不运动）」。显示独立上传耗时，日志输出 `PRELOAD_TIMING`。上传不包含在后续单点运行计时里。
5. 选择 `0: (0°,0°)` 或需要的点，点击「运行选中预载点」。按业务需要再选择1、2、3、4，最后5返回原点。每次只执行一个点，不自动顺序跑完。
6. 可把另一条路线上传到库2、3、4；在同一连接中切换已上传的库编号，会恢复对应路线、速度、容差和点选择，不需重复上传。修改草稿、速度或容差后当前草稿需重新上传。
7. 原「开始联动计时」仍按整张表自动执行往返测试，用于对照性能；它与逐点事件触发是两个按钮。表格和CSV新增 `tol` 终点容差列，TIMING日志新增 `finish_tolerance_deg`。

停止或关闭窗口取消后续动作并停止两轴。断线后GUI清除本地预载选择，避免误用旧状态；重新连接后明确预载再运行。预载点“返回0”是按已有坐标返回±0.2°范围，不是重新回零或重建参考。

## 推荐给同事的SDK用法

SDK速度为**真实输出轴rpm，不除以6**；GUI速度输入仍沿用实际rpm=设定值÷6。下面0.25rpm等价于GUI填写1.5。

```python
import time
from app import MotorController

points = [(0,0), (6.9,0), (16.1,-9.7), (24.8,0), (16.1,9.7), (0,0)]

with MotorController('tcp://192.168.10.50:5000',
                     timing_log='logs/motion_timing.jsonl') as motor:
    # 前提：两轴已建立参考且停稳。只需在任务开始前调用一次。
    route = motor.preload_route(points, route_id=1, speed_rpm=0.25,
                                tolerance_deg=0.2)
    print('上传与封存总耗时ms:', route['upload_elapsed_ms'])

    # 实际项目把下面调用放在“该去下一个点”的事件处理里。
    # 不要在上传后不加区分地自动运行所有点；采集时机由业务软件决定。
    point_index = 1
    caller_begin = time.perf_counter()
    done = motor.move_preloaded_point_and_wait(1, point_index, timeout_s=120)
    caller_elapsed_ms = (time.perf_counter() - caller_begin) * 1000

    assert done['completed']
    print('两轴实际完成快照:', done['positions'])
    print('SDK总耗时ms:', done['elapsed_ms'])
    print('下发到应答ms:', done['accepted_ms'])
    print('应答到完成ms:', done['wait_ms'])
    print('各轴板端准备ms:', done['board_prepare_ms'])
    print('调用包装等额外开销ms:', caller_elapsed_ms - done['elapsed_ms'])
    # 复用positions作为这一轮位置/速度/报警/参考核验；没有固定停稳后sleep。
    # 业务事件到caller_begin之前的排队、判断，以及返回后的DAQ操作要另计时。
```

若要不阻塞业务线程，可在专门控制线程中运行组合接口；事件/GUI线程不要同步等待它。接口内部必要的状态轮询仍通过同一连接串行执行，不要另开高频状态查询争用总线。

| API | 行为 |
|---|---|
| `preload_route(points, route_id=1, speed_rpm=0.1, tolerance_deg=0.2, token=None)` | 上传并封存；本地先验证全部点格式，板端校验参考、范围、静止、模式。返回库编号、令牌、点、速度、容差、就绪状态和上传总耗时。不会运行点 |
| `get_preloaded_route(route_id=1)` | 读取token、速度、容差、点数、已上传数和ready；不运动 |
| `run_preloaded_point(route_id, point_index, token=None)` | 非阻塞运动提交：只发送一条0x43，不做额外PC预检/停止；返回ACK及板端准备ms，尚不代表到位。默认使用本SDK预载令牌，跨实例可显式提供token |
| `move_preloaded_point_and_wait(route_id, point_index, timeout_s=120)` | 推荐事件接口：要求本SDK已预载该库。提交一个点并等待，使用库内相同容差，返回直接完成快照和分段耗时。不会自动执行下一个点 |
| `move_axes_to(targets_deg, speed_rpm=0.1, tolerance_deg=0.2)` | 无需预载的双轴点定位，默认新0.2°策略；需v3.9.1固件 |
| `wait_for_axes(targets_deg, tolerance_deg=0.2, timeout_s=120)` | 默认改为0.2°，仍要求实际直接完成证据。显式指定应与板端该任务容差一致 |

如果把板端容差设置为0.2°，却在调用端继续等0.1°或完全等于目标，电机可能已经合法停在0.18°误差处，调用端会一直等到超时。组合接口会自动使用同一份预载容差，避免这一冲突。旧单轴API仍保持各自原有规则。

### 集成时减少额外耗时

`move_preloaded_point_and_wait()`已经核验两轴角度、实际零速、报警、参考及任务完成。成功返回后，可直接使用 `positions`，不必再逐轴STOP、再读速度、再独立全量核验，也不需要无条件额外等待几百毫秒。若采集平台另有稳定性条件则单独记录和判定。

请将外部耗时拆成“业务事件→进入SDK”“SDK内部elapsed_ms”“SDK返回→开始采集”。只有SDK内部数据无法定位业务队列、GUI线程、DAQ停启和磁盘写入。不要把网络ACK或SDK返回成功前的阶段当作已经可以采集。

## 协议：固定库0x40～0x44

所有请求Device=1，Parameter=库编号1～4；整数均大端。token是非零uint32上传代次标识，不是安全认证凭据。SDK不自动重发运动。

| Command | 请求Data | 成功应答Data |
|---|---|---|
| 0x40 BEGIN | `>IHHB`，9字节：token、真实0.01rpm、容差毫度、点数1～16 | 状态11字节 |
| 0x41 POINT | `>IBii`，13字节：token、从0开始且顺序递增的点编号、两轴绝对毫度 | 状态11字节 |
| 0x42 SEAL | `>I`，4字节token | 状态11字节；ready=1才可调用 |
| 0x43 RUN | `>IB`，5字节token和点编号 | `>II`，8字节各轴准备ms；后续0x37查询完成 |
| 0x44 STATUS | 空 | 状态11字节 |

状态编码为 `>IHHBBB`：token、速度、容差、总点数、已上传数、ready。旧token、未封存、越界点、参考失效或活动任务会被拒绝；RUN不会自动打断正在执行的其他点。

0x1A/JP在v3.9.1兼容原10字节请求（原严格完成范围），并支持12字节 `>HiiH`，末尾是10～500毫度的终点容差。SDK新双轴默认发送12字节，旧固件会拒绝，禁止降级重发。0x1B板端诊断和0x37直接/缓存来源规则不变。

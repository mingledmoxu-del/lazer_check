# P100S 驱动框架

> 2026-09-08 更新：已新增 `p100s_bench` 台架速度调试模块并接入 main。
> 当前上电仍只读，但支持调试器命令进行参数检查、PA-53 暂存使能、限时低速试转和停止。
> 最新操作以 [P100S_上机调试步骤.md](P100S_上机调试步骤.md) 为准；下文“当前启动行为”及“运动扩展”描述的是此前基础通信版本。

采用 MassageRobot 的 C 对象风格：`xxx_handle_s` / `xxx_handle_t`，方法与变量使用小写下划线，对象指针为方法第一个参数。不分配堆内存，不引入 C++。

## 文件与职责

| 文件（相对 LightCheck 工程目录） | 职责 |
|---|---|
| Communication/Inc/rs485.h、Src/rs485.c | UART、方向 GPIO、静默帧边界、总超时 |
| Communication/Inc/modbus_rtu.h、Src/modbus_rtu.c | 03/06、CRC、响应校验、异常码；不依赖 HAL |
| Motor_driver/Inc/p100s.h、Src/p100s.c | 参数组地址、PA 暂存地址、状态解码 |
| Core/Src/main.c | 创建对象、每次轮询结束后间隔 500ms 再读取状态 |
| tests/test_p100s.c | 使用模拟传输测试实际 Modbus 和 P100S 源码 |

对象组合为 `p100s_handle_t → modbus_handle_t → rs485_handle_t`。同一总线的多个伺服对象共享一个 Modbus 对象，使用不同站号；不同物理串口分别创建总线对象。Modbus 通过 `exchange(context, ...)` 注入传输方法，便于测试和替换硬件。

## 当前启动行为

USART3 为 9600/8N2，PC10 TX、PC11 RX、PC12 方向。程序初始化站号 1，只读取 0x1000～0x1013，不写参数、不自动使能。PG6 在每次轮询后翻转，只是心跳，不表示通信成功。

`main.c` 中 `P100S_RS485_TX_LEVEL` 默认 `GPIO_PIN_SET`，假定 PC12 连接收发器的 DE 与 /RE；接线必须与该配置一致。若实际是其他接法，调整方向适配层。默认接收低电平也已由 GPIO 初始化设置。

调试器观察 `servo_motor.last_result`、`exception_code`、`status_valid` 和 `status`。只有最近一次 `p100s_read_status()` 成功时 `status_valid` 才为 1；失败后保留旧值但标记无效。它不保证数据永远新鲜，停用轮询后应用需要自行判断采样时间。速度保留为 `speed_raw`，其他单位/缩放以目标固件资料为准。

## 调用示例

```c
rs485_handle_t servo_port;
modbus_handle_t servo_bus;
p100s_handle_t servo_motor;

/* GPIO 与 UART 初始化之后；每一步均应检查返回值。 */
rs485_init(&servo_port, &huart3, RS485_RE_GPIO_Port,
           RS485_RE_Pin, GPIO_PIN_SET);
modbus_init(&servo_bus, &servo_port, rs485_exchange, 400U);
p100s_init(&servo_motor, &servo_bus, 1U);

if (p100s_read_status(&servo_motor) == MODBUS_OK) {
    int32_t position = servo_motor.status.position;
    (void)position;
}

uint16_t value;
if (p100s_read_parameter(&servo_motor, P100S_GROUP_PA, 4U, &value) == MODBUS_OK) {
    /* value 为当前控制方式，可交给应用处理。 */
}

/* 显式选择保存方式。此例为 PA-34 暂存值，地址 0x00A2。
 * value 的范围、缩放和运行条件须由应用按设备参数要求确认。 */
modbus_result_t result = p100s_write_parameter(&servo_motor, P100S_GROUP_PA, 34U, 100U,
                      P100S_STORAGE_TEMPORARY);
/* 应用检查 result，失败时不假定写入成功。 */
(void)result;
```

读写参数接口只检查地址分组边界；PA 编号限定 0～127，以防误入暂存区。P3/P4 暂存写入被拒绝。不是每个组内地址都一定存在，参数值也没有统一范围。普通写入可能保存 EEPROM，不应循环重复配置。更改 PA-71/72/73 后需要同步主站配置；部分参数需要重启。通用 Modbus 层保留原始寄存器访问能力。

## 收发与错误处理

- 发送前排空残留接收数据，并观察 6ms 静默；阻塞 HAL 发送成功已等待 TC，随后立即回到接收方向。
- 首字节受剩余总超时限制，后续字节以 6ms 静默结束一帧；默认一次事务预算 400ms，包括前置静默、发送和响应。
- 当前是适合 9600/8N2 的宽松毫秒级帧接收器，未实现精确的 RTU 1.5 字符中断帧判定。需要严格时序时改为定时器/中断接收；不要直接用于其他波特率。
- 检查完整帧长度、站号、功能码、CRC、03 字节数及 06 完整回显；最大读取 100 个寄存器。错误时不更新调用者输出。
- 区分参数、忙、超时、UART、帧格式、CRC 和设备异常；设备异常码在对象 `exception_code`。
- 不自动重试写操作。写入超时可能已经执行，应用应先读回确认。Modbus 无事务编号，严重迟到响应与下一次相同请求无法完全区分，需按设备最大响应时间安排重试。
- 每条总线只能串行调用，不能在 ISR 中调用或与其他 UART DMA/中断收发混用。`busy` 仅防重入，不能替代 RTOS 互斥锁。

## 运动扩展

当前已在 PC 二进制协议中实现 PA 读写、PA53 软件强制使能、内部速度 1 启停、状态读取、PA61 报警复位，以及基于 P4 位置命令 1 和 P3-18 强制 CTRG/HOLD 的相对/绝对位置与点动。速度模式使用 PA4/PA22/PA24，位置模式使用 PA4/PA14/P4-0/P4-2~4。首次使用必须空载低速核对驱动器固件对这些参数的响应；软件急停依赖串口和 RS485，不能替代独立硬件急停回路。

## 编译与测试

在 LightCheck 工程目录执行 `cmake --preset Debug` 和 `cmake --build --preset Debug`。

主机测试（Windows 已安装 LLVM/MSVC SDK）：

```powershell
& 'C:\Program Files\LLVM\bin\clang.exe' -std=c11 -Wall -Wextra -Werror -ICommunication/Inc -IMotor_driver/Inc tests/test_p100s.c Communication/Src/modbus_rtu.c Motor_driver/Src/p100s.c -o build/test_p100s.exe
& .\build\test_p100s.exe
```

测试不包含实际电气接线、PC12 极性、真实 UART 时序或驱动器固件兼容性，这些需要板上验证。

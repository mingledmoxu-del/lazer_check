# v3.8.6：到位速度、反馈刷新与停稳确认延迟

## 发现的问题

v3.8.5的0x19使用剩余计数×120/PA11，即2/秒比例项，临近目标持续降低速度，短距离换点可能始终达不到请求速度。另有独立等待：SDK坐标定位先stop再调用会再次stop的相对运动；有参考复位还套一轮。GUI停止确认首查120ms、两次零速间隔150ms，之后流程/报警/新动作常再各等80ms。主界面及调试反馈请求原本约750ms/1000ms一次。

## 修改

1. 保留0x19/PT及全部API签名。按剩余距离、PA41减速时间和PA42平滑时间求可用速度上限，不再使用固定比例长尾。请求速度仍为上限，不保证小距离能到满速。整数二分求解，预留反应距离；反应时间按采样间隔两倍加20ms估计，范围100～1000ms。PA41表示1000→0电机rpm的毫秒数；每次任务读取真实值，不修改驱动参数。
2. 每周期实读位置，反馈单位最多每秒复查一次。新鲜的控制采样（≤200ms）供PC查询复用；READ_AXES返回样本年龄和缓存标识，过期再读。GUI运动时主位置请求周期200ms、调试250ms，空闲维持原频率。
3. SDK坐标定位及已有参考复位复用本次操作完成的停稳与反馈，避免嵌套重复stop；不跨操作缓存停稳状态。SDK stop仍实读连续两次零速，复查等待100ms→20ms。
4. GUI停止复查120/150ms→20ms；确认后到调试后续动作、报警查询、排队新动作的固定80ms等待改为0。保留报警检查、两次零速和旧回调代次隔离。20ms是调度等待，不是承诺停稳耗时。
5. 固件定位开始先读实际速度，已经零速时不再写一次停止。速度模式停止仍核对全部4组内部速度及速度源，已为零/已选择的项不再重复写；非零项继续写入并读回。

## 使用方式

同时烧录本版LightCheck.hex并更新上位机/SDK。坐标定位调用一次`move_to_angle()`/`move_to_zero()`即可，它们包含停止确认，不必外层再重复stop及轮询。网口地址端口设置、速度设定÷6、限位和坐标参考规则不变。停稳、报警、参考或通信不满足条件时仍拒绝后续运动。

## 验证与限制

12组C测试、178项Python测试、H743构建与GUI构造检查；覆盖正常到位/换向、制动模型、反应时间及S曲线加大时降速、有限减速模拟、未停稳禁止新启动、两次真实零速、SDK坐标定位仅一轮停止、通信/反馈单位异常。

本次没有连接真实板子或发起运动。软件制动距离是基于参数与采样周期的模型，不是实际制动性能测量，无法保证消除现场延迟或超调。请先用行程中间小角度低速验收到位及换向，再比较换点耗时。记录“调用开始→停止应答→第二次零速→新命令应答→开始移动→到位”的时间，可区分物理减速、网络/RS485与上层业务等待。

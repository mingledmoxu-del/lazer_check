## 同事程序已有预设轨迹：提前预载，触发时只启动

适用场景：完整软件里已经保存／计算好了两轴角度轨迹，希望按下执行按钮时不要再等整条轨迹上传。**不需要打开本调试GUI，不需要修改已配套的v3.0下位机；直接调用现有SDK即可。**

这是一种调用时机优化：把上传放到设备准备／选择预设阶段，触发阶段只发启动请求。**本节没有实现批量高速上传，也没有提高串口速率或实时控制频率。** 驱动器启动前的参考／起点检查、模式初始化仍有耗时，不能承诺零延迟或精确到指定毫秒启动。

### 推荐业务流程

1. 设备准备：连接串口，建立两轴可信参考、确认软范围并启用，检查方向／报警／SON。SDK不会自动建立参考或修改使能。
2. 选择预设：将同事程序的数据转换为`TrajectoryPoint(time_s, axis1_deg, axis2_deg)`，在控制工作线程调用`prepare_trajectory(points, ...)`。它会停止旧动作、完整上传并校验，成功返回READY；**不会自动走到首点，也不会启动轨迹**。
3. 进入待执行状态前：通过已确认安全的定位流程分别移到预设首点并停稳，或者在预载前就完成起点定位。不要擅自把未知位置设成零来通过检查。
4. 显示“预载就绪”：保存返回的`session`，保持串口对象／控制线程可用。READY阶段不需要轨迹心跳，也不需要循环重复上传；STM32通电且会话未被替换／取消时，缓冲会保留。
5. 收到执行触发：校验会话仍为READY，再调用`start_trajectory(session)`。**此处不要再调用`prepare_trajectory`，也不要重新逐点下发。** 启动后SDK自动维持心跳；业务线程读取状态，或调用`wait_trajectory`等待DONE。
6. 停止／故障／本轮完成后：应用层将“就绪”标记清除。再次运行前重新预载；现有固件不支持同一个结束／取消会话直接重播。

预设轨迹的时间单位为秒、角度为减速器输出角度，必须是按本机构换算后的两轴目标角，不能直接拿屏幕像素／空间坐标作为角度。电机1以水平0°、传感器参考+25°为基准，电机2为其软件参考坐标。限制仍是2～128点、首点t=0、点间隔≥50ms、总时长1～600秒。

### 可复制的预载／触发封装

以下类供同事嵌入现有程序，不会在导入／构造时连接或运动。所有方法由同一个控制工作线程串行调用；界面按钮只向该线程提交动作，不在UI线程里等待串口。

```python
from app import MotorController, TrajectoryPoint


class PresetMotion:
    def __init__(self, motors):
        self.motors = motors
        self.ready_session = None
        self.duration_s = None

    def preload(self, preset_rows):
        # preset_rows: [(time_s, axis1_deg, axis2_deg), ...]
        # 选择新预设时，先撤销应用层旧的“就绪”，失败后不得沿用旧会话。
        self.ready_session = None
        points = tuple(TrajectoryPoint(t, a1, a2) for t, a1, a2 in preset_rows)
        prepared = self.motors.prepare_trajectory(
            points, cycle_ms=100,
            max_speed=0.5, max_accel=1, max_error=0.75, tolerance=0.3,
        )
        # 原始点须满足这些约束，否则先延长时间或用business_trajectory重新规划。
        # 现场验证通过后，才按“日常运动参数建议”逐项提高。
        self.ready_session = prepared.session
        self.duration_s = prepared.duration_s
        return prepared  # 成功时state=2（READY）；业务界面此时才允许触发。

    def start_preloaded(self):
        if self.ready_session is None:
            raise RuntimeError("尚未预载成功，不能启动")
        status = self.motors.get_trajectory_status()
        if status.session != self.ready_session or status.state != 2:
            self.ready_session = None
            raise RuntimeError("预载会话已失效／不再READY，请重新预载并检查现场")
        session = self.ready_session
        self.ready_session = None  # 一次性消费，启动失败／结果未知也不自动重试。
        return self.motors.start_trajectory(session)

    def stop(self):
        self.ready_session = None
        return self.motors.stop_trajectory()


# 在现有程序的设备连接／准备流程里创建一次，并保留对象：
# motors = MotorController("COM6", timeout=4.0).connect()
# preset = PresetMotion(motors)
# 完成现场参考、保护配置及安全起点定位后：
# preset.preload(your_existing_preset_rows)  # 提前做；成功后显示“预载就绪”
#
# 之后收到执行事件，在同一控制工作线程中调用：
# started = preset.start_preloaded()        # 只启动，不重传整条轨迹
# finished = motors.wait_trajectory(started.session,
#                                  timeout=preset.duration_s + 15)
#
# 程序退出：motors.close()，默认尽力停止两轴并关闭串口。
```

`prepare_trajectory`可能需要数秒，应在选择预设／设备准备时执行，不要放在每次触发回调中。预载未返回成功前禁用执行按钮；用户取消、换预设、重置参考或异常时，还要取消业务队列里尚未执行的“启动”动作，不能在预载结束后自动补发旧点击。停止请求不能仅排在大量业务任务之后。

### 哪些情况要重新预载？

| 情况 | 处理 |
| --- | --- |
| 通电待机，仍是同一READY会话，参考／范围／路径都未变化 | 不必反复上传，触发时校验READY后启动 |
| 换成另一条预设，或修改时间、角度、速度／加速度约束 | 重新调用`prepare_trajectory`，更新session |
| 已完成、手动停止、故障或上传失败 | 旧会话不能直接重启；核查现场后重新预载 |
| STM32掉电／重启／重新烧录 | RAM缓冲和参考丢失；重新建立参考、配置保护并预载 |
| 断线重连、重新回零／人工参考、修改软范围 | 应用层撤销旧“就绪”，核对现场后重新预载，不自动沿用旧坐标关系 |

同事程序可以在PC保存很多条预设，但**STM32当前只保留一条RAM轨迹**，没有多轨迹编号库、Flash掉电保存或运行中追加点。预载另一条会替换原缓冲；执行中不能上传下一条。若需连续执行多轮，可事先把多轮拼成一条时间连续、完整满足范围／速度／点数限制的轨迹，再预载一次，而不是重复启动旧session。

### 如何确认集成没有把上传放错位置？

- 选择预设／准备阶段应出现0x30（BEGIN）、多条0x31（POINT）、0x32（SEAL），随后进入READY。
- 按执行按钮时可先有0x34（查询状态），然后应是0x33（START）；**不应再次出现整串0x30／0x31／0x32**。
- 运行期间主要是0x36（心跳）和0x34（缓存状态），不是反复调用旧定角接口。
- 两轴并非硬同步；v3.2总线升为115200并增加共同减速，仍须实测跟随精度和实际控制周期。

## v3.1 一键双轴小幅调试（无需填写轨迹参数）

主窗口和“两轴轨迹试验”窗口都有 **一键双轴小幅调试** 按钮。使用步骤：

1. 连接STM32；两轴先建立可信参考、开启经过确认的软范围并停稳。此按钮不会自动回零、置零、使能SON、复位报警或扩大范围。
2. 点击按钮，程序依次读取固件任务状态及两轴实际配置、参考角度、转速、报警。若有其他任务、参考无效、软范围未开启、端点触发或余量不足，明确提示并停止流程。
3. 弹窗列出两轴当前姿态、运动幅度及硬输入策略。人工确认机械／线缆安全、SON就绪、人员避让和急停可用后，程序自动生成、上传、校验并启动，不再要求手动定位到27°或填写多个参数。
4. 两轴以各自当前位置为中心，同相正弦往返一圈，计划20秒，结束回到起点附近；这不是圆轨迹，也不是严格硬同步。正常幅度±2°，按两轴较小可用余量一起缩小，最低±1°；若当前位置距任一软边界不足3°则拒绝，不会扩范围。
5. 随时点主窗口“停止”或轨迹窗口“停止两轴”。准备／上传期间的停止、关闭、断线、通信失败同样取消自动启动；不会稍后突然执行。运行中停止遵循原组停机流程，不能代替硬件急停。

固定预设：控制周期250ms，最大速度1.5°/秒，最大加速度3°/秒²，最大跟随误差0.75°，终点容差0.3°，33个点。轨迹点从当前位置出发且回到同一位置；一键模式确认后会把预设及预览填入面板。上传中改编辑值会取消自动启动，须重新确认。

本次只修改上位机、离线轨迹辅助函数及测试；**已有配套v3.0固件无需重新烧录**。尚未升级到轨迹固件的设备仍需先烧录v3.0。初次实机测试仍需有人看护，已知不安全的机械姿态不能仅凭软件角度／软范围来判断。

## v3.0 两轴轨迹模式（实验功能）

- 新入口：主窗口右侧“两轴轨迹试验”。支持两轴角度CSV导入、离线正弦示例、预览首点、完整上传／校验、明确启动、两轴停止及误差／调度统计。
- STM32维护共同时间轴及缓冲，运行中只更新速度，不再每点停止和切模式。SDK新增`prepare_trajectory`、`start_trajectory`、`get_trajectory_status`、`wait_trajectory`、`stop_trajectory`，点模型和示例生成器从`app`直接导出。
- 上下位机都必须更新。v3.2使用115200波特率RS485，允许50～500ms周期、GUI默认100ms；实际频率受总线耗时限制。尚不能承诺5秒精确空间圆。角度正弦示例不等于真实末端圆，同事须根据机构几何生成角度轨迹。
- 上传不启动，两轴必须已建立参考、开启软范围并停在首点；不自动预定位。任一轴限位／通信／跟随误差等故障取消整组，心跳3秒超时请求停机，迟到心跳不能重启。
- 轨迹1～600秒、2～128点、点间隔至少50ms。定角／回零原功能不变；运行中不得混用旧运动、改参数或改参考。
- 首次以幅度约2°、周期20秒试验，完成保护验收再逐步尝试5秒。完整CSV格式、接口参数、协议、状态码、限制及实机步骤见[新增轨迹文档](../docs/两轴轨迹接口与验收.md)。

### 当前版本需要一起交接哪些内容？

1. 整个`app`文件夹，包含本README、启动脚本、依赖清单、协议和接口实现；不要只发`main.py`。
2. 配套v3.0下位机源码／编译固件，并实际烧录到STM32。仅更新上位机不能增加轨迹执行能力，也不能让旧固件获得触发修复或水平姿态。
3. 机械方向、传感器通道／极性、回零安全侧、参考姿态及行程范围的实测记录。配置和参考只存在RAM，不能依靠JSON草稿恢复“已回零”。

现有ZIP不会随源码更新，交接前重新打包。GUI和API不能同时打开同一个串口。当前协议没有固件版本／标定版本握手，不能只凭串口连接成功判断版本匹配。

## 2026-10-19 速度模式停止修复

旧固件在当前速度模式（监视寄存器0x1009=1）只清零PA24。当PA22选择模拟量、点动、键盘速度，或SP1/SP2选择PA25～PA27时，PA24写入成功不代表当前速度指令归零，可能出现“正在停止”但实际持续旋转。

配套新固件先临时清零PA24～PA27并逐项读回，再临时设置PA22=1并读回；任何失败均不返回停止成功。四档清零完成前不会切换速度来源。位置模式仍使用HOLD/CTRG流程，不修改SON或DI映射。GUI收到停止应答只提示参数写入已应答，实际停止仍以转速监测确认。

该修复不修改驱动器保存的上电配置，也不能阻止STM32尚未建立通信时的上电运动。上电即转时，先使用现场硬件停机方式停止，在外部SON关闭时读取并记录两轴PA4、PA22、PA24～PA27，核对SP1/SP2和模拟量输入接线；若使用混合模式，还需核对CMODE来源。不要根据14～16rpm单独断定是模拟量漂移。重新上电后临时参数会恢复保存值，应按实际控制方案整改上电配置与使能顺序。

验证：新增停止回归覆盖PA22六种来源、四档残留速度、轴隔离、写入超时和读回不一致；8组主机侧C测试、90项Python测试和STM32目标编译通过。尚未实机验证停止效果、减速时间或上电行为。更新时须重新烧录STM32固件，仅重启上位机不会修复旧固件停止逻辑。

## v2.2 停止换向和自动刷新修复

- 上下位机必须同时更新，电机1的v2.1姿态标定保持不变。停止仍是通信HOLD，不是硬件急停或驱动器内部任务永久删除；未完成任务保持暂停，不得由其他软件/面板独立解除HOLD。
- 位置停止写入HOLD=1、CTRG=0。新位置动作要求实际零速；准备CTRG低电平时保留HOLD，再间隔20ms并再次读取零速；最后同一次写入CTRG=1、HOLD=0，消除提前解除HOLD后旧方向恢复的通信窗口。触发失败不自动重发，尽力重新保持HOLD。
- 每次位置动作将P4-1设为0并读回，使用手册规定的ZSPD零速触发条件，避免延迟CMDOK尚未就绪时丢失新触发。不改SON、不清编码器。寄存器写入成功仍不等于驱动器实际执行目标，必须实机验证本驱动器修订版对同步HOLD/CTRG的响应。
- 自动位置反馈是低优先级查询。用户指令等待已在途的查询回复后优先发送，不插入重叠普通事务，也不等待机械动作完成。刷新不插队到配置/参数查询序列；停止可抢占等待并清除所有未发送动作。查询失败、超时或断线清除待发操作，不会恢复通信后突然发出旧动作。
- 验收：保留硬件急停，低速且远离软/机械边界，先正向小角度→中途停止→确认零速→反向小角度，对照实际转速和反馈方向；再反过来测试。开自动刷新重复，并验证点击操作不再因后台刷新弹忙、停止后无延迟动作。若发正向仍持续负速，立即停止并保存完整日志，不能认定模拟测试已证明驱动器实机任务被替换。

## v2.1 电机1固定姿态（v2.2继续沿用）

- 电机1固定以水平为0°、抬头为正、传感器最终回零姿态为+25°。换算在STM32执行，不是仅更改界面文字；电机2仍按原来的相对坐标处理。
- 反馈姿态=相对传感器参考的输出位移+25°。原来相对+10°现在为+35°，原来相对−25°现在为水平0°。
- 默认软范围为−35°～+35°，建立人工参考或传感器回零成功后自动启用；上电无参考不自动启用、不自动运动。下限−35°按用户“反方向相同”设定，尚需实机确认，不应直接跑边界。
- 电机1可缩小软范围，但不能通过范围命令扩大到±35°以外，范围还必须包含水平0°和参考+25°。显式关闭软策略会失去行程约束，正常运行不要关闭；配置/重新接线时先停机。限位不是安全级保护，需停止余量。
- 电机1的人工参考按钮必须在抬头+25°的传感器参考姿态点击，不能在水平处点击。`set_current_zero(1)`兼容名称的含义也改为此参考，建议集成调用`set_current_reference(1)`；不会清空编码器。
- `get_feedback(1).output_angle_deg`、`move_to_angle(1, angle_deg)`和`get_guard_config(1)`的范围都使用水平姿态坐标；`move_relative`依旧是增量，不加25°偏移。
- 如输入原点位于+25°、但仍需向正向走到+35°，不能把该原点当正端硬限位，应确认它是中间原点并采用软范围。先确认正向命令确实抬头，否则不能使用此标定。
- 当前须同步更新并烧录配套v2.2固件；v2.1起才包含此标定，旧固件仍回报相对坐标，界面不能自动识别旧固件的标定版本。重新上电后必须重新建立参考。25°目前是用户提供的近似标定，不是倾角传感器测量值。

```python

with MotorController("COM6") as motors:
    # 先完成配置并传感器回零，或在真实+25°姿态人工捕获参考。
    print(motors.get_feedback(1).output_angle_deg)  # 回零成功后约+25°
    motors.move_to_angle(1, 0, speed_rpm=0.1)  # 水平；仅表示命令被接受
```

## 1. 系统与使用前提

通信链路：PC → USB串口 / STM32 USART1 → RS485 / Modbus RTU → 两台P100S → 电机与减速器。

- Motor 1、Motor 2 对应驱动器站号1、2。
- PC与STM32：115200 / 8N1；STM32与驱动器：115200 / 8N2（v3.2默认；PA72=1152、PA73=0保存复位）。
- 两轴减速比均为50:1。运动接口的角度、速度均指**减速器输出轴**。
- STM32读取PA11、换算脉冲、写入驱动器参数并触发；驱动器执行加减速和闭环控制。
- DB44外部SON由硬件控制；本GUI/API不发送Servo ON/OFF，也不自动修改使能参数。
- 固件须支持二进制协议的0x14输出轴运动和0x15加减速命令；旧ASCII固件不兼容。
- GUI/API不能同时占用同一个串口。API不启动界面、不依赖Tkinter。

**当前保护策略：** 通过“位置/限位/回零调试”面板或API按轴配置、读取实际策略。DI0～DI5始终可采样，下位机刚上电时硬限位和软范围都关闭，输入角色未分配；上电不会自动回零，也不会自动应用配置文件。电机1成功建立参考后会自动启用软范围，电机2须明确启用。先验证接线和电平，再确认实际策略。
旧固定两输入实验实现的 `MOTOR_LIMITS_ENABLED` 和旧PC `LIMIT_FEATURES_ENABLED` 保持0/False，不要用它们启用v2.0策略；新策略由 `axis_guard` 模块独立处理。原有旁路入口仍隐藏，API不提供自动旁路。
下位机检查输入触发、位置和回零过程，界面只负责请求和显示。参数及软件零点只存RAM，MCU重启后必须重新读取/配置并建立零点；不能沿用旧界面值。软件停机仍依赖RS485和主循环，不能替代硬件急停/硬限位。新功能必须烧录配套固件，旧ZIP不会自动更新。

## 3. 文件职责与自动连续旋转

### 自动连续旋转（v1.9）

在界面“自动连续旋转”区域输入输出轴角速度（默认5°/秒）、选择方向，点击“开始自动旋转”并确认提示。先停止旧动作、确认零速和报警后，进入驱动器速度模式，持续转动；不是每秒重复发一条5°定角指令。
点击“停止自动旋转”或原来的红色“停止”均可停止。自动旋转期间锁定电机选择，避免误停另一轴；更换电机、改方向或转定角动作前，先停止并确认停稳。修改输入数值不会立即改变正在执行的速度。

STM32负责角速度换算：电机rpm = 输出角速度(°/秒) × 50 / 6。由于驱动器速度以整数rpm设置，5°/秒会取整为42rpm，实际指令约5.04°/秒，不保证累计角度精确；需要精确总角度仍使用定角运动。
运行有加减速过渡，不是上电瞬间达到设定速度。全程须有人看护，确认行程和线缆允许连续转动；限位是否启用应读取下位机实际策略。启用软范围时禁止无终点连续旋转，请使用定角/坐标定位。

GUI/API每约1秒发送该轴心跳，STM32在最后一次心跳5000ms后请求停止并等待零速，失败重试。此看门狗独立于限位开关；断线、程序关闭或停止续期不会自动重启。5秒是心跳期限，不是保证的停止时间，串口阻塞、通信故障和机械减速都会增加延迟，硬件急停仍必需。
必须重新编译烧录配套固件，旧固件会返回未知命令。请重新打包上下位机ZIP，不要发送原来的旧压缩包。

连续速度使用PA22=1、PA24内部速度1。固件会检查P3-0～5，若存在CINV/SP1/SP2（功能9/10/11）物理映射会拒绝启动并返回参数非法，避免被端子切到其他速度或反向；不会自动重写SON和其他DI映射。启动前清除对应软件强制位，并先把旧PA24置零再切换速度模式。

## 4. 独立API快速使用

将整个 `app` 目录复制进调用项目，保证其父目录在Python模块搜索路径中。从本项目根目录即可导入。

只查询，不使能、不运动：

```python
from app import MotorController

controller = MotorController("COM6", timeout=2.0)
controller.connect()
try:
    print(controller.get_status(1))
    print(controller.get_status(2))
finally:
    controller.close(stop=False)  # 仅查询示例：关闭串口，不额外发送停止
```

有人看护的动作示例：

```python
from app import MotorController, MotorError

try:
    with MotorController("COM6") as motors:
        motors.set_motion_profile(1, accel_ms=1500, decel_ms=1500, s_curve_ms=100)
        receipt = motors.rotate_forward(1, 5.0, speed_rpm=0.2)
        print("命令已接收，不代表到位：", receipt)
        input("观察运动；按回车停止，再测试反向：")
        motors.stop(1)
        motors.rotate_reverse(1, 5.0, speed_rpm=0.2)
        input("观察反向运动；按回车停止并退出：")
        motors.stop(1)
except MotorError as exc:
    print("控制失败，请核查现场状态：", exc)
```

此示例由人工结束观察，不是自动判定到位。`with`退出会尝试停止两轴再关闭连接；失败会报告，不会假装已经安全停止。

## 5. 公共接口

| 接口 | 单位、行为与返回 |
| --- | --- |
| `MotorController(port, timeout=2.0, gear_ratio=50.0)` | 构造对象，不连接、不运动；timeout为单条通信等待秒数 |
| `connect()` | 连接串口，返回自身，不使能、不运动 |
| `move_relative(id, angle_deg, speed_rpm=0.2, stop_timeout=10.0)` | 输出轴有符号相对角度；正数正向、负数反向。先停旧动作，再下新动作，返回 `MotionAccepted` |
| `rotate_forward(id, angle_deg, speed_rpm=0.2)` | angle_deg必须为正数；正向定角转动 |
| `rotate_reverse(id, angle_deg, speed_rpm=0.2)` | angle_deg必须为正数；反向定角转动 |
| `start_continuous(id, degrees_per_second=5.0)` | 有符号输出角速度，正值正向、负值反向；先停旧动作，返回 `ContinuousRotation`，自动开启后台心跳 |
| `check_auto_rotation()` | 周期检查后台心跳异常，失败抛MotorError；不会自动重发启动 |
| `stop(id, wait=True, timeout=10.0)` | 通信停止，默认等待连续两次实际转速为0；超时不发送后续运动 |
| `get_status(id)` | `MotorStatus`：motor_id、motor_rpm、output_rpm、run_state、alarm_code |
| `read_alarm(id)` | 原始报警码，0为无报警 |
| `reset_alarm(id)` | 故障排除后显式调用，先停止并确认零速再复位，返回复位后报警码，不重启运动 |
| `read_pa(id, parameter)` | PA原始16位无符号值；有符号参数由调用方按手册解释 |
| `read_position_raw(id)` | 驱动器反馈的有符号32位原始位置计数，不是输出角度或机械绝对零点 |
| `get_feedback(id)` | 实际/指令/偏差计数、P3-32/PA11/PA95、有效软件角度或None、输入位图、回零阶段、故障和转速 |
| `get_guard_config(id)` | 读取下位机实际输入映射、触发电平、方向、保护开关与范围 |
| `configure_inputs(id, negative=None, positive=None, home=None, active_high=True)` | 输入编号0～5或None；负/正限位不得共用，原点可与一个端点共用；须先显式关闭旧策略 |
| `set_soft_range(id, minimum_deg, maximum_deg)` | 设置范围，不自动启用保护；电机1不得超出±35°且须包含0°和+25°，电机2须包含0° |
| `set_guard_policy(id, hardware=..., soft=..., home_direction=0, confirmed=False, home_at_end=False)` | 显式启用策略；确认回零须给出-1或+1方向，软限位须先有有效零点 |
| `set_current_zero(id)` | 兼容名称：电机1捕获+25°参考并启用软范围，电机2捕获0°；切换P3-32显示单位，不清编码器多圈数据 |
| `set_current_reference(id)` | 推荐的人工参考接口；电机1须在真实+25°参考姿态，电机2参考为0°，行为与兼容接口`set_current_zero`相同 |
| `move_to_angle(id, angle_deg, speed_rpm=0.2)` | 先停止，读取有效软件角度，转为相对移动；不是未经回零的机械绝对定位 |
| `start_homing(id, speed_deg_s=0.5, max_travel_deg=30, backoff_deg=2, timeout_s=90)` | 启动STM32回零状态机及后台心跳；要求策略、方向确认、原点输入和初始状态都有效 |
| `wait_homing(id, timeout=125)` | 等待回零成功且零点有效；失败/取消/超时抛异常，不自动重试 |
| `get_motion_profile(id)` | `MotionProfile(accel_ms, decel_ms, s_curve_ms)` |
| `set_motion_profile(id, accel_ms=1500, decel_ms=1500, s_curve_ms=100)` | 先停轴，临时应用PA40～42并读回校验，返回MotionProfile |
| `prepare_trajectory(points, ...)` | 上传完整的两轴时间轨迹并校验，不启动；详见轨迹集成文档 |
| `start_trajectory(session)` | 启动已校验会话，要求两轴已在首点并有有效参考／软范围 |
| `get_trajectory_status()`／`wait_trajectory(session, timeout=30)` | 缓存状态／等待DONE；有跟随误差、调度间隔和故障，非成功状态不能冒充完成 |
| `stop_trajectory(wait=True, timeout=10)` | 停止整个两轴任务并取消旧执行，不续跑 |
| `close(stop=True)` | 默认尝试停止两轴再关闭；失败仍关闭并报错；stop=False仅关闭连接 |

id只能是整数1、2。速度必须为正，方向用角度正负表示。传输分辨率为0.01rpm、0.001°，实际输出速度还受驱动器电机整数rpm取整影响。
`gear_ratio` 只用于API转速显示和输入预校验，**不会修改STM32的减速比**，当前保持50且必须与固件一致。

现提供显式启动的传感器回零及有效软件坐标定位，但不提供上电自动回零、断电零点恢复或完整的定角“等待到位”保证。0rpm也可能表示未启动、暂停或报警，不等于达到目标角度。`wait_homing`只判断本文定义的回零流程完成，不替代机构精度验收。

## 6. 加减速

连续旋转调用示例（调用期间不要再启动GUI占用串口）：

```python
from app import MotorController

with MotorController("COM6") as motors:
    receipt = motors.start_continuous(1, degrees_per_second=5.0)
    print(receipt.actual_deg_per_sec)  # 当前50:1配置约5.04°/秒
    input("连续转动中，按回车停止：")
    motors.check_auto_rotation()      # 正式软件应在自己的定时器/工作线程中周期检查
    motors.stop(1)                    # 取消该轴心跳，发送停止并确认零速
```

`start_continuous(1, -5.0)`为反向。返回值包含motor_id、requested_deg_per_sec、motor_rpm、actual_deg_per_sec；只是指令接收及取整结果，仍需观察实际转速。
API后台线程只续期，不重复启动；对象必须保持存活。`close(stop=False)`也会取消心跳，但不保证立即停止，最多等STM32心跳超时后才请求停止，所以动作结束请显式stop或使用默认close。

- PA40：从0到1000电机rpm的线性加速时间常数，1～10000ms。
- PA41：从1000到0电机rpm的线性减速时间常数，1～10000ms。
- PA42：S型平滑时间，0～1000ms；0为梯形，大于0为S型平滑。

这些不是当前动作的总加速时间。参数临时生效，不写驱动器EEPROM；掉电后恢复此前保存值。

## 7. 集成与错误处理

- API为同步阻塞接口；界面软件应通过工作线程/动作任务队列调用，不要阻塞UI主线程。
- 单次串口事务有互斥锁；复合动作仍须由调用方统一调度，不要多个线程同时控制同一轴。
- 每次新定角动作会先停止旧动作并确认零速，不是轨迹拼接接口。
- `MotionAccepted` 只表示命令已接收，不证明SON有效、机构已动或已到位。API不把运行状态3当作唯一放行条件，外部SON由硬件决定，须核对实际反馈。
- `get_status()` 的转速和报警来自顺序查询，不是同一时刻的原子快照。
- `CommunicationError`：超时、串口异常、应答损坏。运动可能已经执行，**绝不自动重发**；连接进入不确定状态，关闭后重连并核查实际位置。
- `CommandRejected`：STM32返回失败状态，带 `.status` 和 `.response`；例如0x03驱动器无响应、0x04参数非法、0x06忙、0x08下位机保护拦截。通信类状态0x01/02/03/05不证明驱动器从未执行动作，同样会将连接标记为不确定，不能直接重发运动。
- `DriveAlarm`：运动前发现报警，带 `.alarm_code`，不发送新运动。
- `MotorError`：上述异常公共基类，也用于停止确认超时、参数读回不一致等。
- `ValueError`：输入参数错误；被本地校验拒绝的运动不会先发送停止/运动帧。
- 不自动复位报警后继续运动。关闭串口、程序崩溃或STM32复位均不能保证机构停止，必须有独立硬件急停。

超时后的 `close()` 只会尽力发送停止，无法保证收到确认；机构状态必须视为未知。停止确认timeout也不是硬实时停止保证，底层通信本身可能耗时。

## 8. 协议摘要

请求：`AA 55 | Length | Device | Command | Parameter(BE,2B) | Data | CRC16(低字节先)`。
响应在Command后增加Status字节。请求Length=6+Data字节数，响应Length=7+Data字节数。
0x14数据：`uint16 输出速度×100 + int32 有符号输出角度×1000`，均大端；成功返回接收角度×1000（有符号32位）。
PC不产生脉冲波形；STM32用50:1和PA11计算指令。未来软件优先调用API，不复制多套CRC、重试和角度换算代码。

连续旋转新增0x17：数据为int32有符号输出角速度×1000（大端，°/秒），成功返回int16有符号电机rpm。
续期0x18：parameter固定0x4352，无数据，成功返回int16电机rpm。只有已启动且未过期的连续旋转可续期；停止或超时后的迟到心跳返回忙，不会再次启动。

## 10. 位置数据与回零调试顺序

通过RS485读取驱动器已经解码的编码器反馈，不需要STM32直接接编码器信号：0x1001/02为实际位置低/高字，0x1003/04为指令位置，0x1005/06为位置偏差。
数据单位由P3-32决定：0/1按电机编码器分辨率，2/3按PA11分辨率；PA95为编码器分辨率指数，只读，不要改成PA11值。软件坐标仅在已验证的P3-32=3且PA11未变时有效。

```python
from app import MotorController

with MotorController("COM6") as motors:
    f = motors.get_feedback(1)
    print(f.actual_counts, f.commanded_counts, f.error_counts)
    print(f.display_mode, f.counts_per_motor_rev)
    print(f.output_angle_deg)  # 未建立/已失效时为None，不假装0°
```

同一坐标和单位下，输出位移角度 = 反馈计数变化 / 每电机圈反馈计数 / 50 × 360°。这表示净位移，不是来回运动的累计总路程。PA11不能直接当成所有模式的编码器计数。

推荐先在调试面板按如下顺序操作：

1. 读取反馈和DI状态，分别遮挡、解除、断开传感器验证输入；不使能运动。
2. 选择每轴输入角色并应用映射；一个原点可与同轴一个端点共用，未来新增传感器只需重新映射。未使用通道保持“未使用”。
3. 小角度低速核实命令方向及实际转角，明确原点在端点还是中间、从哪一侧接近，填写方向和总预算。
4. 先只启用硬输入策略并确认回零方向；软范围暂不开。初始输入触发时回零被拒绝，先人工检查，不自动猜方向退出。
5. 点击“开始传感器回零”，全过程有人看护。停机/退出失败/搜索超限均不能当作零点；中途停止会取消回零且零点失效。
6. 回零成功后读取实际反馈和保护配置：电机1应显示约+25°并已启用软范围；电机2为0°，需要显式设置／启用软限制。人工捕获参考不等于传感器回零，电机1必须在真实+25°姿态执行，电机2为所需0°位置。
7. 按姿态／软件坐标定位并对照实体角度检查。电机1输入0°为水平，+10°为抬头10°，负角度为低头；主窗口“输出轴角度”仍是相对转动幅度。重新建立参考会改变物理软限位的基准，须保留停止余量。

回零成功的零点是最终停稳后的反馈位置，不是硬件锁存的传感器边沿；减速距离、机械回差和光电开关重复精度都会影响重复性，必须实测。
JSON只保存编辑草稿，加载不会下发/运动，方向确认及硬软保护勾选会清除；CSV最多导出最近10000条反馈。

## 11. 调试面板常见问题

### 为什么全部显示“未读取映射”？

自动刷新发送0x20，只读取位置和DI反馈；它不能代替0x24读取实际输入配置。先选对应电机，点击“读取下位机实际配置”。若尚未配置，通道会显示“未使用”；编辑输入角色／极性，再点击“应用输入映射（先关闭保护策略）”，随后程序会读取实际配置及反馈。读取实际配置会覆盖编辑框，未应用的编辑值不是下位机状态。

### 为什么未安装的DI电平也是1？

未接输入可能为高电平，raw=1只是采样结果，不等于该通道承担限位保护。没接的通道保持“未使用”。检查已接传感器时，先保持SON关闭，观察同一通道遮挡／解除时是否变化，再按实测选择触发电平；电平不变时查接线，不通过翻转极性消除提示。

### 原点触发是否就表示已回零？

不是。“原点触发”是传感器输入状态；“回零完成”是STM32经过寻找、停稳、退出、二次接近、最终停稳后建立参考的状态。电机1的+25°原点位于工作范围中间，若要继续抬头到+35°，应配置为中间原点，不要同时映射成正端硬限位。

### 为什么开启软范围后不能自动连续旋转？

连续旋转没有终点，会绕开有限目标角度检查，因此固件拒绝。保留软范围并改用定角或坐标定位；不要为了连续旋转关闭正常运行所需的保护。

### 自动刷新期间点击按钮，还需要等多久？

需要等已经发出的查询返回，不需要等机械转完；实际等待受RS485通信影响，不承诺固定毫秒数。只有后台位置刷新可让位，已有前台事务仍须串行处理，前台忙提示不代表电机未到位。停止会抢占并取消待发动作；普通查询不会并行挤到同一串口上。

### 停止后换向是否已经保证实物不会继续旧方向？

v2.2修复了代码里的提前释放HOLD窗口，并增加稳定零速、P4-1读回及失败不重发。仍须用配套固件在实物上低速、小角度验证。“STM32已接受”和0rpm都不是新目标执行／到位证明。若新指令与持续实际转速方向相反，立即停机、保留包含停止前后的完整日志，不连续重复试转。

### 重启后能直接按原来的坐标运动吗？

不能。输入配置、软件参考和策略存于STM32 RAM，掉电或重新烧录后需重新读取／配置并建立参考。JSON只保存编辑草稿，不保存可靠当前位置；它不会自动应用，更不会自动回零。
